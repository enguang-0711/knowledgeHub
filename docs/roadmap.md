# 通用测试与质量工程学习路线

这条路线先建立跨行业通用能力，再选择一个系统或行业专题练习。建议按产物验收，不以看完课程或记住名词作为完成标准。每周 6–10 小时，可在约 10–12 周完成基础主干；已有经验时可跳过熟悉部分，但应保留可复现练习。

## 路线总览

| 阶段 | 建议时间 | 核心能力 | 可验收产物 |
|---|---:|---|---|
| 0 | 1 周 | 需求、风险与测试边界 | 风险分析和系统边界图 |
| 1 | 2 周 | 测试分析与用例设计 | 可追踪的测试集与覆盖说明 |
| 2 | 2–3 周 | Python、Git 与自动化框架 | 一条可重复运行的自动化套件 |
| 3 | 1–2 周 | 数据、指标与实验设计 | 指标计算脚本和解释清楚的报告 |
| 4 | 1–2 周 | 日志、状态与证据治理 | 单次运行可复核的证据包 |
| 5 | 1–2 周 | CI、趋势与质量门禁 | 可追踪的持续集成流程 |
| 6 | 2 周 | AI 应用测试与评估 | 有标注集、基线和错误分析的评估报告 |
| 7 | 按需 | 选择行业或系统专题 | 一个领域内可演示的端到端项目 |

## 阶段 0：需求、风险与边界

把需求改写为“初始状态、输入/动作、可观测结果、时间界限、异常处理和恢复”。区分被测系统、依赖服务、测试设备、数据源和判定器；记录接口假设、不可观测区域及安全/隐私约束。

**练习：**选一个登录、搜索或设置类需求，画出关键组件和观察点；给每个验收条件指定证据源。

**通过标准：**其他人能据此复现用例，并能指出某条断言失败时需要查看的证据。

**本阶段学习卡片**

- **先修：**需求阅读和基本软件生命周期概念。
- **重难点：**避免把实现细节当需求；“请求成功”“状态已改变”“用户看到正确结果”是不同断言。
- **学习文档：**[模板与检查清单](/templates)、[知识地图](/knowledge-map)。
- **B 站学习入口：**[搜索：软件测试需求分析与测试用例设计](https://search.bilibili.com/all?keyword=%E8%BD%AF%E4%BB%B6%E6%B5%8B%E8%AF%95%E9%9C%80%E6%B1%82%E5%88%86%E6%9E%90%E4%B8%8E%E6%B5%8B%E8%AF%95%E7%94%A8%E4%BE%8B%E8%AE%BE%E8%AE%A1)。

## 阶段 1：测试分析与用例设计

掌握等价类、边界值、判定表、状态迁移、组合测试、探索式测试、风险优先级和需求追踪。为用例标注前置条件、数据、步骤、期望结果、清理动作和失败严重度。区分正向、负向、异常、权限、兼容性和恢复场景。

**练习：**为一个可用的 Web/API 示例设计覆盖正常、空值、越界、重复提交和权限不足的用例，并说明每一项覆盖的风险。

**通过标准：**用例集既覆盖需求，也覆盖边界和失败恢复；重复用例有明确的保留理由。

**本阶段学习卡片**

- **先修：**基本需求拆解和逻辑条件。
- **重难点：**组合空间会迅速增长；用风险和 pairwise 等方法控制规模，但不能漏掉安全关键组合。
- **学习文档：**[测试用例模板](/templates)、[实战练习入口](/vehicle-voice/testing/projects)。
- **B 站学习入口：**[搜索：等价类边界值状态迁移测试设计](https://search.bilibili.com/all?keyword=%E7%AD%89%E4%BB%B7%E7%B1%BB%E8%BE%B9%E7%95%8C%E5%80%BC%E7%8A%B6%E6%80%81%E8%BF%81%E7%A7%BB%E6%B5%8B%E8%AF%95%E8%AE%BE%E8%AE%A1)。

## 阶段 2：Python 与自动化工程

掌握 Python 包结构、类型注解、数据类、异常边界、日志、文件与 JSON/YAML 处理、虚拟环境和依赖锁定。学习 pytest 参数化、fixture、marker、超时、报告扩展、资源清理及 Robot Framework 的关键字编排。将用例数据、执行器、系统适配器和断言职责分开。

**练习：**对一个公开 API 或本地 mock 服务编写测试；模拟超时、错误响应和依赖不可用，并生成带用例 ID、输入摘要、运行版本和失败原因的报告。

**通过标准：**在干净环境按 README 安装后可重复运行；失败能追溯到用例、阶段和输入。

**本阶段学习卡片**

- **先修：**基础编程、命令行和 Git。
- **重难点：**fixture 生命周期、异步等待、超时和资源回收；固定 sleep 与无限重试会掩盖真实问题。
- **学习文档：**[Python、Pytest 与 Robot Framework](/automation-framework)、[pytest 官方文档](https://docs.pytest.org/en/stable/)、[Robot Framework 用户指南](https://robotframework.org/robotframework/latest/RobotFrameworkUserGuide.html)。
- **B 站学习入口：**[搜索：Python pytest 自动化测试 fixture 参数化](https://search.bilibili.com/all?keyword=Python%20pytest%E8%87%AA%E5%8A%A8%E5%8C%96%E6%B5%8B%E8%AF%95fixture%E5%8F%82%E6%95%B0%E5%8C%96)。

## 阶段 3：数据、指标与实验设计

为指标定义目标对象、样本单位、分子/分母、排除条件、切分维度和版本。掌握混淆矩阵、precision/recall/F1、错误率、分位时延、稳定性、配对比较和小样本不确定性。保留原始结果与派生结果，数据转换过程应可追踪。

**练习：**准备一个含已知正确/错误预测的公开或合成数据集，计算分类指标；再改变样本比例，观察 accuracy 与 macro F1 的差异。

**通过标准：**报告能说明指标如何计算、使用了哪些样本、分层后差异在哪里以及比较的局限。

**本阶段学习卡片**

- **先修：**集合、比例、均值与分位数。
- **重难点：**分母、过滤规则和分组方式常比公式更容易造成误读；平均分可能掩盖少数关键类别的退化。
- **学习文档：**[质量指标与统计方法](/vehicle-voice/testing/metrics)。
- **B 站学习入口：**[搜索：软件测试质量指标 precision recall F1 统计](https://search.bilibili.com/all?keyword=%E8%BD%AF%E4%BB%B6%E6%B5%8B%E8%AF%95%E8%B4%A8%E9%87%8F%E6%8C%87%E6%A0%87%20precision%20recall%20F1%20%E7%BB%9F%E8%AE%A1)。

## 阶段 4：可观测性与证据

关联测试输入、请求/会话标识、结构化日志、状态变化、截图或外部观测，形成单次运行的证据链。记录时间戳来源和时钟误差；区分产品失败、环境失败、数据错误、采集器故障和未判定结果。对原始证据使用稳定命名和保留策略。

**练习：**在 API/mock 项目中为每次运行创建 run id，将请求、应用日志、最终状态和测试报告关联起来；故意关闭日志采集，确认系统不会把证据缺失报成产品通过。

**通过标准：**一条失败能在不依赖执行者记忆的情况下复查；原始数据与解析后的结论可互相追溯。

**本阶段学习卡片**

- **先修：**日志、状态码、时间戳和文件系统基础。
- **重难点：**多个数据源时间不一致、动态界面和采集器失效会造成假结论；要显式报告盲区。
- **学习文档：**[CI 与质量趋势](/ci-quality)、[实验记录模板](/templates)。
- **B 站学习入口：**[搜索：软件测试可观测性日志追踪故障定位](https://search.bilibili.com/all?keyword=%E8%BD%AF%E4%BB%B6%E6%B5%8B%E8%AF%95%E5%8F%AF%E8%A7%82%E6%B5%8B%E6%80%A7%E6%97%A5%E5%BF%97%E8%BF%BD%E8%B8%AA%E6%95%85%E9%9A%9C%E5%AE%9A%E4%BD%8D)。

## 阶段 5：CI、回归与趋势治理

按反馈速度和资源成本分层测试：静态检查、单元/组件、集成、端到端和受控硬件测试。学习流水线触发、并发隔离、超时、重试、缓存、环境健康检查、制品归档和质量门禁。建立可解释基线，按版本、平台、功能、数据集等维度分析趋势。

**练习：**把离线套件接入 GitHub Actions，在 PR 上运行快速检查、定时跑完整集，并归档机器可读结果与失败日志。

**通过标准：**从报告可追溯代码、依赖、测试数据和执行环境；重试与基础设施失败不会掩盖产品回归。

**本阶段学习卡片**

- **先修：**Git、测试分层和可重复构建。
- **重难点：**并行资源冲突、环境漂移和过宽重试策略会使 CI 结果失真。
- **学习文档：**[CI 与质量趋势](/ci-quality)、[GitHub Actions 文档](https://docs.github.com/actions)。
- **B 站学习入口：**[搜索：GitHub Actions 自动化测试持续集成](https://search.bilibili.com/all?keyword=GitHub%20Actions%20%E8%87%AA%E5%8A%A8%E5%8C%96%E6%B5%8B%E8%AF%95%E6%8C%81%E7%BB%AD%E9%9B%86%E6%88%90)。

## 阶段 6：AI 应用测试与评估

区分传统确定性软件、包含模型的组件和完整生成式 AI 应用。为任务定义代表性数据、参考答案或评分规则，测试提示/模型版本变化、格式、事实支持、拒答、鲁棒性、延迟和成本。LLM Judge 需要和人工标注集校准；RAG 需要同时检查检索和答案引用；关键业务结论应保留可审计的规则或人工复核。

**练习：**选一个低风险的文本分类或检索问答 demo，构造正常、边界、对抗和无答案样本；对比模型版本，分类记录正确、错误、拒答和不确定结果。

**通过标准：**评估结果可复放、可分层、可追踪版本，模型不可用或输出不合格时流程能安全失败或回退。

**本阶段学习卡片**

- **先修：**测试数据设计、分类指标和版本控制。
- **重难点：**单一总分无法覆盖生成质量；判分模型也会错，需用人工标注对照其偏差。
- **学习文档：**[大模型应用测试与评估](/llm-testing)。
- **B 站学习入口：**[搜索：大模型应用评测集 LLM Judge RAG 评估](https://search.bilibili.com/all?keyword=%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8%E8%AF%84%E6%B5%8B%E9%9B%86%20LLM%20Judge%20RAG%20%E8%AF%84%E4%BC%B0)。

## 阶段 7：选择系统或行业专题

通用主干完成后，按工作方向学习领域特有的架构、设备、协议、数据授权和验收规范。车载语音与视觉专题分别提供开发和测试入口，可从[车载领域导航](/vehicle-cases)选择对应路线；语音测试覆盖声学、语料、车载集成和 HIL。

## 每周学习闭环

选一个可验证问题，先写假设和判定方法，再准备数据、运行实验、保留原始证据、分析失败，最后将可复现结论写成知识页。每篇学习记录至少说明适用范围、依赖版本和已知限制。
