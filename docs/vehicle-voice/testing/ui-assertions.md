# 车机界面断言

## 可观察内容

车机 UI 可提供识别文本、确认/澄清提示、执行状态、错误提示和音区/会话标识。优先使用稳定的无障碍节点、测试接口或结构化 UI 状态；截图/OCR 适合补充而非取代确定性接口。

## 视觉识别和容错

使用 OCR 时固定分辨率、字体缩放、语言、主题和截图时机。定义文本归一化、区域、置信阈值和重试策略；屏幕动画或短暂转场不能误判为业务完成。

## 跨模态一致性

将屏幕提示与日志事件、车辆/应用状态和播报事件关联。UI 显示“已完成”不一定意味着底层状态成功；失败路径也要确认界面提示正确且不会留下过期卡片。

## 练习与验收

实现一条媒体查询用例，通过可访问性节点断言状态，再用截图作为失败证据。注入延迟、屏幕转场和错误提示，验证判定器区分成功/处理中/失败。

## UI 断言稳定性

优先从无障碍节点或测试接口获取状态，保存节点 ID、文本、可见性和业务标识；截图/OCR 需要固定分辨率、语言、主题、字体比例、区域和截图时机。异步动画使用有界轮询和稳定窗口，避免短暂过渡页被判成功。

**验收产物：**覆盖处理中、成功、澄清、错误和旧卡片残留的样例；把 UI 结果与 trace 事件及业务状态回读关联。OCR 低置信、节点缺失或画面不可读应产生明确失败证据，且界面显示成功不能替代底层状态断言。
