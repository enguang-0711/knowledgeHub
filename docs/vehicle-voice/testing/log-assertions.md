# 语音日志与事件断言

## 事件契约

将一次请求按 trace/session ID 关联音频开始、唤醒、VAD、ASR partial/final、NLU、业务调用/回读、TTS 和会话结束事件。字段需包含事件时间、时钟域、模块/版本、状态码和必要的脱敏上下文。

## 断言设计

校验事件顺序、唯一性、必需字段、状态转换和时间预算。避免对易变的自然语言日志全文做硬编码匹配；优先断言结构化事件码。缺失日志本身应成为可定位的测试失败。

## 时间关联

跨进程/设备时间不同步时记录时钟偏差或使用统一单调时钟。关联窗口应考虑采集和传输抖动，避免把相邻请求的事件串在一起。

## 练习与验收

构造成功、超时、重复回调和缺事件日志，编写结构化校验器。失败报告能指出预期事件、实际序列、trace ID 和证据位置。

## 结构化事件校验

定义每种事件的 schema、必需字段、时钟域和状态码；以 trace/session ID 区分并发请求。校验事件顺序、次数、关联 ID、状态转换及时间预算，并允许协议明确的可选事件/重试路径。对自然语言日志仅做辅助检索，不把易变文案作为唯一判据。

**验收产物：**包含成功、缺事件、乱序、重复回调、错 session 和时间回跳的 fixture；失败消息指出期望/实际事件、样本 ID 和证据位置。日志缺失或字段脱敏导致无法判定时应报不可判定，而非通过。
