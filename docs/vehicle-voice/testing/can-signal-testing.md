# 车载 CAN 信号测试

## 信号契约

从项目批准的 DBC 或接口规范确认报文 ID、信号位宽、字节序、缩放、偏移、单位、有效范围、周期、超时和无效值。DBC 文件也要纳入版本管理；不能凭经验臆造车辆信号定义。

## 语音业务闭环

验证从语义请求到车机服务调用、报文发送、目标 ECU 状态回读和 HMI/TTS 反馈的完整关系。请求被接受、报文已发送和车辆状态已变化是不同结果。检查重复命令、超时、权限拒绝和总线不可用。

## 安全边界

只在获批的仿真器、隔离台架或明确授权环境执行。控制类信号需遵守项目安全策略和硬件联锁；回归脚本应有清晰停止条件，避免连接真实车辆后意外触发动作。

## 练习与验收

使用虚拟 CAN 或台架回放一个低风险状态查询，校验编码/解码、有效值和超时。保存原始帧、解码结果、软件版本和状态回读证据。

## 报文与业务状态的联合断言

从版本化 DBC/接口契约加载 ID、信号位、字节序、缩放偏移、单位、周期和无效值；先用边界值验证编码/解码，再运行查询或低风险命令的完整语音业务流程。对每个请求关联 ASR/NLU、服务调用、原始帧、ECU/仿真回读和用户反馈时间。

**验收产物：**DBC 与软件版本、原始帧、解码状态、超时/重复/拒绝场景结果和独立回读证据。仅在获批 mock、虚拟总线或隔离台架操作；“报文已发”不能被算作“车辆状态已完成”。
