# Android 车机与 ADB 测试

## 设备和应用边界

车机应用测试需要记录设备型号、系统镜像、权限、音频策略、应用版本和服务依赖。ADB 可用于安装、启动、日志采集和受控输入，但不同车机对调试接口的开放受项目权限和安全策略限制。

## 自动化要点

优先通过稳定的 intent、测试接口、无障碍节点或设备适配器操作；截图/OCR 作为补充。等待应用状态、音频焦点、录音路由或服务事件时使用有界轮询，不依赖固定长延时。

## 故障处理

覆盖应用重启、权限丢失、设备离线、音频焦点冲突和日志缓冲清理。用例应标记是否重启设备、是否修改系统状态，并保证结束后恢复初始环境。

## 练习与验收

在授权的模拟器/开发机上安装测试应用、启动一条查询流程并保存 logcat 与 UI 证据。注入设备断连，验证测试报告将环境失败与产品失败区分。

## 自动化执行与环境恢复

每次测试保存设备型号、系统/build fingerprint、应用/服务版本、权限、音频路由和测试前状态。先在模拟器或获批开发设备验证安装、启动、查询流程，再采集 logcat、结构化事件和 UI 节点；设备操作和修改系统设置应可逆并记录。

用有界轮询等待音频焦点、服务连接和业务状态，避免固定长延迟掩盖竞态。**验收产物**包括执行命令、设备 ID、初始/结束状态和失败归类；断连或权限不足应标为环境问题并完成设备清理，不应误报产品成功。
