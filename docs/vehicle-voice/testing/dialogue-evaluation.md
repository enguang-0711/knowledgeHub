# 对话管理与多轮测试

## 状态和场景

多轮用例应定义初始会话状态、每轮输入、期望意图/槽位、补槽或澄清结果、业务调用和最终状态。覆盖确认、拒绝、取消、改口、超时、重复事件、唤醒新会话、用户打断及不同音区并发。

## 判定方式

检查状态迁移、上下文归属、会话 ID、工具/业务调用次数、最终车辆或应用状态和用户反馈。不能只比对最终播报文本；错误动作可能仍被正确播报。每个预期动作应有独立证据源。

## 隔离与恢复

验证会话重置不会泄漏旧槽位；多音区测试需确认说话人/区域标签在整个链路中保持一致。设备断连和服务重启后检查未完成对话是否安全取消或可恢复。

## 练习与验收

编写一条“调节温度—补充数值—改口—取消”的脚本，记录每轮输入、状态差异和证据。注入重复回调与超时，确保业务动作恰好执行预期次数。

## 多轮用例编写方法

每条用例定义初始状态、轮次输入、ASR 文本、意图/槽位、预期澄清、业务调用次数、状态变化和最终反馈。覆盖补槽、纠错、否定、取消、超时、重复回调、打断、新会话和跨音区并发；每轮用独立 session/trace ID 记录状态快照。

**验收产物：**状态转移轨迹、业务状态独立回读、日志/UI/TTS 证据和断言失败位置。通过“服务接受但状态未变”“重复回调”“用户中途取消”等故障用例，验证不会重复或迟到执行旧动作。
