# 车载语音系统架构

## 学习目标

能从麦克风输入一路追踪到业务状态和用户反馈，划分模块、进程、线程、设备与网络边界，并为每条边界定义可观测事件和失败语义。

## 端到端数据流

典型链路包括音频驱动与路由、AEC/降噪/波束形成、唤醒与 VAD、ASR、NLU、对话状态、业务适配器、车辆或应用服务、TTS 与 HMI。实际产品可能将部分模块合并、放在 DSP/SoC/云端或通过车机服务访问；架构图应标清运行位置、数据格式、采样时钟、同步方式和网络依赖。

## 边界与接口

模块接口应说明输入所有权、缓冲区生命周期、线程安全、时间戳时钟域、错误码、取消语义、背压策略和版本兼容。音频块应带序号和时间戳；识别事件至少区分 partial、final、拒识和取消；业务调用结果要区分“请求已接收”和“状态已确认”。

## 延迟、资源和降级

架构评审时分解端到端延迟预算，识别复制、格式转换、队列和跨进程调用的成本。明确 CPU/DSP/NPU、内存、网络和功耗预算。网络断开时可切换到本地能力，但要明确功能范围变化；模型未加载、麦克风断流和车机服务重启均需有可恢复状态。

## 工程产物

维护组件图、时序图、接口 schema、线程/队列图、资源预算、故障模式表和日志字段定义。每项关键结论都要关联软件、模型、配置和硬件版本，便于复现线上问题。

## 练习与验收

画出一个离线优先语音功能的部署图和时序图。注入断流、云端超时、重复业务回调和模型加载失败，说明每个事件如何被检测、记录、恢复并反馈给用户。

## 架构拆分与时序预算

画出采集/驱动、音频前端、唤醒/VAD、ASR、NLU/对话、车辆服务和 TTS 的数据及控制流，标记同步/异步接口、缓冲所有者、会话 ID、时钟域和每段预算。区分车端离线处理与云端服务的网络依赖、隐私边界和降级路径。

评审线程与队列模型：音频回调中不能做阻塞推理或无界日志；队列满要定义丢弃/背压策略。请求重试与业务调用要可追踪且幂等，避免网络恢复后重复执行旧动作。

**验收产物：**模块图、接口/schema、时序图、资源预算和故障状态表；用一次断网/服务超时演练验证架构定义的离线能力和用户反馈。
