# 语音可观测性与数据闭环

## 可观测事件

使用一次请求的 trace/session ID 关联音频帧、前端状态、唤醒、VAD、ASR partial/final、NLU、业务响应与播报事件。不同设备时钟要能换算或记录同步误差；日志字段必须标注模型、配置和软件版本。

## 从问题到改进

线上失败经授权和脱敏后形成错误样本，经过分类、复核、标注、数据集更新、训练/规则变更和固定集回归，再按版本灰度发布。错误标签要区分声学、识别、语义、业务接口和用户体验问题。

## 防止数据闭环偏差

只收集系统判断为失败的样本会遗漏静默失败，也会过度代表少数用户或场景。建立抽样审计和分层覆盖，记录筛选策略、人工复核比例和样本来源。

## 练习与验收

从一次模拟失败生成完整 trace，定位到阶段和样本；按流程形成一个修复版本，并证明固定回归集、保护集及版本记录都更新。

## 可追踪的语音问题闭环

用 trace/session ID 关联音频帧范围、设备/配置/模型版本、前端状态、VAD/唤醒、ASR/NLU、业务回读和 TTS 事件；跨设备时间需记录时钟偏差。实时统计队列延迟、丢帧、资源水位和错误码，同时避免默认记录原始对话内容。

样本回流先确认用途授权和最小化脱敏，再做完整性/去重、人工标签复核和场景分层；回流集、调参集与冻结评估集严格分开。修复后将匿名化失败用例固化到版本化回归语料。

**验收产物：**从一次线上模拟失败追到具体阶段、制品和样本，完成修复对照、固定集回归与发布/回滚记录；证据应足够定位，又不暴露不必要个人语音。
