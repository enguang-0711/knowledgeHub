# 唤醒词、VAD 与端点检测

唤醒词检测决定系统何时进入交互；VAD 估计是否存在语音；端点检测判断一句话何时开始/结束。它们常共享音频前端和流式状态，但判定目标不同。

## 概念和状态

- **唤醒词：**监听候选短语并决定是否开启会话，需处理相似词、噪声、回声和低能量说话。
- **VAD：**按帧分类语音/非语音或估计语音概率，为识别、功耗和端点提供线索。
- **起始检测：**确认用户开始说话，过高延迟会截掉词首，误触发会送入无关音频。
- **端点检测：**在语音停止后经过等待/稳定策略提交 final；等待过短会截尾，过长会增加响应延迟。
- **打断：**TTS 播放时检测新用户输入并暂停/取消旧播放，需与回声消除和会话状态配合。

实现通常有阈值、连续帧计数、hangover（语音结束后的保留时间）和状态机。具体阈值依音频前端、噪声、帧长和产品时延要求而定，不存在通用固定值。

## 设计权衡

误唤醒、漏唤醒、噪声误触发、首字截断、末字截断和端点延迟是不同指标。通过降低阈值减少漏唤醒可能增加误唤醒；缩短静音等待可降低延迟但可能提前结束长停顿语句。需在代表性车内条件上联合评估。

## 调试信号

保存逐帧 VAD 概率、唤醒分数、状态迁移时间戳、音频能量和 ASR 开始/结束事件。测试静音、风噪、媒体回声、短语停顿、拖长词尾、打断和连续请求。关注真正“无人说话”的监听时长，误唤醒率应有明确暴露时间分母。

## 练习与完成标准

实现一个有限状态原型：Idle → Wake → Listening → Endpoint → Final，并加入取消和超时。对同一波形扫不同阈值/等待时间，绘制误触发、漏检和端点延迟之间的变化；交付状态日志和边界样例。
