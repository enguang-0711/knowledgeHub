# 车机语音系统集成

语音算法最终通过音频 HAL/驱动、车机服务、应用接口和车辆信号连接到真实产品。集成需保持音频路由、服务会话、车辆状态和 HMI 反馈之间的时序和语义一致。

## 音频路由和车机服务

明确输入源、采集设备、采样率/格式、通道/音区、优先级、焦点管理和媒体/通话并发策略。服务接口定义请求 ID、会话、事件顺序、超时、错误码和版本。设备重启、应用切换或音频焦点变化后，要验证路由恢复。

## 车辆和应用接口

将语音结构化结果映射到受控业务 API，不直接在识别回调中写车辆总线。定义权限、参数范围、状态回读、去重和失败反馈。接口变化应有版本兼容策略；模拟器、台架和量产车的能力差异需明确。

## 线程与时钟

区分音频采集时钟、系统单调时钟、服务端时间和总线时间。用请求/会话 ID 关联音频块、识别、语义、服务调用、状态变化和播报。跨时钟源做延迟分析时记录偏移和不确定度。

## 故障路径

覆盖音频设备不可用、HAL 重启、ASR 服务断连、总线服务超时、TTS 播放失败、应用重启和网络切换。每个故障定义用户反馈、重试限制、状态清理和恢复条件。禁止超时后默默复用旧会话或旧意图。

## 练习与完成标准

在 mock 或隔离台架中实现一个从音频流到低风险应用状态的完整 trace；注入音频路由切换、服务断连和车辆状态超时，确认错误可诊断、会话可清理且不会重复执行。
