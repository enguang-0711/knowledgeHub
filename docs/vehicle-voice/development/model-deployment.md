# 语音模型部署与边缘推理

ASR、唤醒、VAD、NLU 和 TTS 的模型部署需考虑输入特征契约、流式缓存、算子兼容和端侧资源。文件成功导出只说明格式生成，不能证明实时服务可用。

## 部署流程

1. 冻结模型、特征参数、词典/标签 schema、阈值和训练配置。
2. 导出到目标运行时支持的格式，记录输入输出名称、张量形状、采样率和帧配置。
3. 检查算子支持、动态维度、量化设置、运行时和驱动版本。
4. 在相同波形上比较训练框架与目标引擎的特征、logits、token 和最终文本。
5. 集成流式缓冲、状态缓存、超时、错误码和会话生命周期。
6. 在目标硬件进行长时、并发、断流重连和资源测量。

## 数值和特征一致性

语音预处理差异常来自重采样、通道选择、窗函数、FFT 归一化、Mel 频带、log 底数、均值/方差、padding 和帧起点。保存“金样本”波形与每层特征，逐级比较。最终文本不一致时，需分辨输入特征、模型输出、解码和文本归一化差异。

## 流式状态和资源

流式模型可能需要缓存 encoder state、卷积状态或预测网络上下文。新会话、取消、采样率变化和重连时应正确初始化/清理。模型服务需限制并发会话、内存和队列；超载时应明确拒绝或降级，而不是无限等待。

## 练习与完成标准

部署一个小型语音模型或运行时样例，配对比较原框架和目标后端的中间特征、logits 与文本；运行连续会话并检查缓存复位。交付模型哈希、工具链、输入契约、误差阈值和设备测量边界。
