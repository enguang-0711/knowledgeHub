# 实时性能与优化

语音交互对首响应、连续音频和尾部延迟敏感。优化应从分段测量开始，并同时观察识别质量、丢帧、资源与热状态。

## 时延分解

分别测量采集缓冲、前端处理、唤醒/VAD、音频传输、ASR 首个 partial/最终结果、NLU、业务执行、TTS 首音和播放完成。端到端统计标明起点/终点、时钟来源和同步误差。首字延迟、句末确认延迟和完整业务闭环延迟不可混为一项。

## 实时音频指标

关注音频欠载/溢出、丢帧/丢块、buffer depth、线程唤醒抖动、CPU/DSP/NPU 使用率、内存、功耗/温度和并发会话数。报告 p50/p95/p99 或项目需要的分位数、样本数、预热、设备/固件和负载条件。

## 优化手段

- 使用有界预分配缓冲区，减少实时路径动态分配与拷贝。
- 限制队列长度，设计背压与过载行为。
- 使用平台支持的低精度推理、算子融合或 DSP/加速器，但配对验证输出质量。
- 异步执行时保持会话、音频序号和输出顺序，避免延迟改善以乱序为代价。
- 精简特征重复计算和不必要的音频格式转换。

## 练习与完成标准

对固定语音套件执行端到端 profiling，找出主要耗时和缓冲等待。实施一项优化后，用相同设备、音频和负载比较延迟分位、WER/任务错误、丢块、内存和温度；不接受只报告模型推理时间的优化结论。
