# C++ 与实时音频工程

车载语音服务常以 C++ 承载音频采集、缓冲、前端处理和推理。实时路径需在截止时间内持续提供音频帧，优先保证有界延迟和安全的资源生命周期。

## C++ 基础能力

掌握 RAII、值/引用、移动语义、智能指针、容器、异常边界和 CMake。音频缓冲区要明确拥有者、容量、有效帧数和释放时机；异步任务不能引用即将被重用的采集缓冲区。避免在热路径无意复制长音频或大型张量。

## 实时音频回调原则

实时回调应尽可能短且时延有界：避免阻塞 I/O、等待锁、动态内存分配和无节制日志。常见设计是预分配缓冲区，通过有限容量的 lock-free 或低争用队列把数据交给工作线程；具体实现需在目标平台验证线程安全和优先级行为。

处理模块要定义块大小、帧数、采样格式和通道布局。缓冲不足、过载和消费者滞后应产生可观测的欠载/溢出计数，而不是静默丢弃。

## 并发与生命周期

区分采集、DSP、识别和播放线程；明确启动顺序、停止信号、队列清空策略和服务关闭时限。避免持有全局锁执行耗时算法。跨线程事件携带采集时间戳、序号和会话 ID；处理完成顺序可能不同于输入顺序。

## 调试和构建

使用 CMake target 管理模块与依赖；为 Debug/Release、目标架构和 SDK 版本建立可复现构建。AddressSanitizer、ThreadSanitizer 和 profiler 可用于开发阶段查内存/竞争/热点，但最终实时表现需在目标构建和硬件上测量。

## 常见问题

- 采集回调调用网络或模型推理，导致音频缓冲溢出。
- 锁竞争偶发阻塞，表现为爆音、延迟突增或丢帧。
- 队列不设上限，系统持续处理旧音频，响应越来越慢。
- 重连后旧回调仍持有对象，产生释放后访问或重复释放。

## 练习与完成标准

构建一个采集模拟器和消费线程，使用固定大小块、有限队列和停止信号。注入消费者变慢、队列满和异常退出，统计丢帧、最大排队时延与资源释放；在目标平台验证回调时限。
