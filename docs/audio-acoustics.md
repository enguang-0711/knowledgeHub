# 音频链路、声学和注入

车载语音测试的音频不是一个 WAV 文件这么简单。实际听到/识别到的信号经过播放设备、车厢声学、麦克风、前端处理和采集链路；其中任何一处变化都可能影响结果。

## 数字音频基础

- **采样率**：每秒采样次数，例如 16 kHz。将 48 kHz 文件标记成 16 kHz 并非重采样，会改变时长和音高。重采样需要低通滤波防止混叠。
- **位深**：量化动态范围；转换位深可能引入量化噪声。保存原始母版，派生文件记录转换工具/版本。
- **声道**：单声道、立体声或多通道布局要清晰。不能把双麦阵列通道混成单声道后仍声称覆盖阵列行为。
- **PCM 与容器**：WAV 是容器，可包含不同编码/位深；校验 codec、采样率、声道、样本格式，不只看扩展名。
- **削波**：数字满幅导致峰值平顶，检查绝对峰值和连续满幅样本；峰值接近 0 dBFS 也可能不代表声学声压足够。
- **静音/电平**：同时看 RMS、peak、时长、首尾静音和有效语音比例。自动归一化会改变系统实际输入条件，除非这正是被测流程。

## 注入方式及覆盖范围

| 方法 | 经过路径 | 适用用途 | 不覆盖/风险 |
|---|---|---|---|
| 离线文件送 ASR 接口 | ASR 软件接口及之后组件 | 算法基线、批量回归 | 不覆盖唤醒、麦克风、AFE、AEC、真实声学 |
| 软件音频注入到设备 | 注入点之后的部分设备链路 | 设备集成、可重复调试 | 注入点前的硬件/前端可能被绕过 |
| 座舱扬声器/人工嘴播放 | 声学空间、麦克风及之后链路 | 端到端声学/HIL 测试 | 受扬声器、位置、房间和校准影响 |
| 真人说话 | 真实说话人变异和自然交互 | 代表性验证、探索性测试 | 重复性较低、采集授权和隐私要求高 |

选方法时明确要验证的系统边界。将播放器插入设备回环可能绕过唤醒或麦克风路径，不能不加说明地称为完整端到端覆盖。

## 声学播放实验设计

1. 固定车厢/台架状态、座椅/玻璃/空调/媒体状态、扬声器与麦克风位置。
2. 校准播放链路电平；记录播放设备、功放、增益、人工嘴设置和校准日期。
3. 确认声道映射及目标音区；多音区测试要说明目标声源位置与竞争位置。
4. 使用参考麦克风或设备回采验证实际到达麦克风附近的声压/波形；记录背景噪声底。
5. 固定测试顺序或随机化条件以减少温度/状态漂移；每种条件重复足够次数。
6. 保存源文件和回采文件，关联同一 run id；失败时保留播放/录音日志。

## 噪声与 SNR

常见干扰包括风噪、胎噪、空调、音乐、乘员交谈、提示音和瞬态敲击。SNR 通常写为语音有效段功率与噪声功率比的 dB 值：

```text
SNR_dB = 10 × log10(P_speech / P_noise)
```

但实际车内噪声通常非平稳、频谱相关，单个 SNR 不能充分描述场景。记录噪声文件/来源、播放电平、频谱或至少场景标签、时间关系（静态/突发/同时/间歇）及测量位置。避免仅用数字混音代替通过扬声器播放的声学噪声，除非目标是算法层压力测试。

ETSI ES 202 396-1 涉及背景噪声仿真技术与背景噪声数据库等内容。引用时核实适用版本、标准标题和项目采用方式；它不是所有车内场景的完整验收标准，也不能替代车厂声学规范。

## 音频资产校验

建议入库前自动验证：可解码、采样率/声道/位深符合接口约定、文件时长在范围内、无 NaN/空数据、静音和削波阈值、音频峰值、哈希唯一、文本/音频关联存在。异常输出应给文件名、检测项、实测值和限值，避免静默自动修复。任何修复都生成新的派生资产并保留父文件哈希。

## 常见实验混淆

- 把播放器音量档位当作 dB SPL；两者没有固定换算关系。
- 同一文件、不同设备回放后波形与声压不同，导致结果不可直接比较。
- 更改系统音量或媒体状态会改变 AEC/AGC 行为。
- 背景噪声和语音分开播放/叠加播放的时序可能影响唤醒和端点检测。
- 测试前缓存、会话上下文、热词或服务状态未清理，造成跨条污染。
