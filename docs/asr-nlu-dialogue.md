# ASR、NLU 与对话管理评测

## ASR 测试维度

- **文本覆盖**：高频指令、罕见词、品牌/人名/地名、数字、日期时间、单位、英文夹杂、同音词、否定词和长句。
- **语音覆盖**：不同音色、性别/年龄段（仅在合法且有依据时）、普通话口音/方言、语速、音量、犹豫、重复和自我修正。
- **声学覆盖**：静音、风噪/胎噪、空调、媒体、多人交谈、重叠语音、远近场、音区串扰、回声和唤醒词相似干扰。
- **服务行为**：partial 更新、final 稳定性、超时、拒识、离线/弱网、断连重连、热词生效、服务降级和恢复。
- **鲁棒性**：长时间输入、连续请求、应用/服务重启、模型切换和资源紧张。

同一条输入如果同时检查最终 ASR、NLU 和业务结果，仍应保留各阶段原始输出，才能区分问题根因。

## 文本归一化

归一化规则需与被测产品验收目标匹配，例如繁简转换、数字汉字/阿拉伯数字、中文/英文空格、标点、单位符号、口语填充词和缩略表达。保留原始文本，另行生成规范文本；每次指标报告记录 normalizer 版本。不要用过度归一化把真正的语义错误消掉，例如把不同温度、方向或否定内容折叠成相同结果。

## NLU 评测

意图测试关注标签集合、层级分类、置信度阈值和错误严重程度。槽位测试关注槽位名、值、单位、实体消歧、缺槽策略、非法值拒绝与归一化。设计成对样本尤其有效：只改变一个 token 或槽位，观察输出是否正确变化，例如“调高两度/调低两度”“播放/暂停”“主驾/副驾”。

## 对话状态机

可以把状态至少建模成：

```text
Idle
  └─ Wake → Listening
       ├─ Final ASR → Interpreting
       │    ├─ Complete intent → Executing → Responding → Idle
       │    ├─ Missing slot → Clarifying → Listening
       │    └─ Unsupported/low confidence → Rejecting → Idle
       ├─ Cancel/timeout → Idle
       └─ Barge-in → stop current response → Listening
```

实际状态名按系统实现映射，不要让测试状态机取代被测系统状态机。测试侧模型的作用是定义预期轨迹和检测意外转换。

## 多轮用例设计

- **补槽**：先给不完整请求，系统询问缺失信息，再补齐。
- **改口**：用户在确认前更改一个槽位，验证最终执行参数。
- **取消/拒绝**：取消待执行动作，确保业务服务没有副作用。
- **打断**：TTS 期间输入新指令，检查旧播报停止和新请求接管。
- **上下文引用**：第二轮使用“再高一点/换成那首”，验证引用对象和边界。
- **会话隔离**：切换用户/音区/重启后历史上下文按产品策略清除或保留。
- **竞态与重复**：重复唤醒、快速连续命令、同一请求重发，检查幂等或去重策略。

每条序列保存逐轮输入、事件顺序、等待窗口、预期上下文变量和最终业务状态。只保存最后一轮答案不足以复盘上下文泄漏。

## 流式结果判定

Partial transcript 允许变化时，断言不要要求每个中间文本都完全固定；可以验证最终稳定结果、最大修订次数、首个 partial 时延及 final 结束条件。需要评测 partial 时，保存事件顺序和时间戳，并定义编辑距离/稳定窗口口径。对流式交互，时间顺序错误也可能是功能错误，即使最终句子正确。
