# 实战项目与阶段验收

项目按设备依赖递增。没有车机、总线设备或商业 TTS 账号时，也可以先完成 mock/开源工具版本，清楚标记模拟覆盖范围。

## 项目一：离线语料与 ASR 指标台（1–2 周）

**目标**：从语料清单读取参考文本和模型输出，生成 CER/WER 及错误对齐报告。

**步骤**：定义 case schema → 校验音频文件属性和哈希 → 冻结文本归一器 → 批量读取 ASR 输出 → 计算 aggregate 与逐条错误 → 按噪声/意图/音色切片 → 导出 JSON/HTML/CSV。

**验收**：同一版本重复运行结果完全一致；故意加入插入、删除、替换各一例能在报告中定位；缺音频或参考文本重复会失败并说明原因。

**扩展**：接入 Whisper/SenseVoice/Qwen-ASR 等作为参考模型时，分别记录模型版本、推理配置和许可；第三方模型分数不是目标车机模型的替代验收。

## 项目二：可复现 TTS 与声学派生集（1–2 周）

**目标**：批量合成用例并制作有来源记录的噪声条件版本。

**步骤**：挑选许可明确的 TTS → 固定 voice/engine/参数 → 保存源文本、SSML、哈希和元数据 → 生成后自动校验 → 以脚本混音生成算法层噪声集 → 另行安排声学播放集 → 人工抽样确认发音和标签。

**验收**：任一音频都可追溯到文本、生成参数、父资产和校验结果；不合格音频不会进入执行集。

## 项目三：端到端设备冒烟（2–4 周，需授权台架）

**目标**：一条低风险指令从声音注入到用户反馈和业务状态全程闭环。

**步骤**：实现音频/车机/事件/状态 adapter → 测试前设备健康检查 → 重置会话 → 播放带标记音频 → 收集 ASR/NLU/服务日志 → 检查独立状态 → 检查 HMI/TTS → 保存所有工件 → 安全恢复基线。

**验收**：分别注入 ASR 错误、业务超时、日志掉线和台架离线，报告能归入不同失败类别；设备恢复失败时后续测试停止。

## 项目四：多轮与音区隔离（2–3 周）

构造补槽、改口、取消、TTS 打断、上下文指代、短时间重复请求和跨音区同时讲话序列。给每轮设置上下文初值、expected event trace、延迟窗口、最终车端状态和会话结束清理规则。

**验收**：识别文本相同但对话上下文不同的样本能区分；前一轮残留、跨音区串话和取消后仍执行都能被捕获。

## 项目五：CI 回归与趋势看板（2–4 周）

**目标**：离线 suite 每次 PR 执行，设备冒烟在受控 runner 执行，夜间跑较大集。

**验收**：输入资产和模型版本固定；失败工件可下载；基础设施失败不混入模型错误率；基线变更有评审记录；阈值展示分母和样本量。

## 项目六：LLM 候选用例助手（持续）

将冻结的产品 schema 与脱敏需求交给模型生成 JSON 候选。用规则验证、人工复核和独立标注集测量有效率、语义错误、重复率和节省的审核时间。

**验收**：模型失效时流程仍可完成；未审核数据不能进入黄金集；提示注入或无效 JSON 不会触发设备操作；每条被采纳用例可追溯来源。

## 一个季度的最小成果定义

在资源有限时优先交付：可浏览 Pages、被版本控制的小型公开/合成语料、离线指标脚本、一个 mock 端到端场景、HIL 接口契约、失败报告模板和清楚的安全/隐私边界。真实设备集成按授权条件逐步增加。
