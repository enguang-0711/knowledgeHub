# 质量指标与统计方法

指标必须附带定义、分母、测试集版本、切分维度、排除规则和置信信息。单个汇总百分数不能说明系统在哪些场景失效。

## ASR：WER 与 CER

将假设文本和参考文本按既定归一化规则对齐，统计替换 `S`、删除 `D`、插入 `I`：

```text
WER = (S + D + I) / N_words
CER = (S + D + I) / N_characters
```

`N` 是参考序列单位数。插入会使错误率超过 100% 是允许的。中文常使用 CER，也可按分词后 token 计算 WER；比较模型/版本时必须冻结分词器和文本归一化规则。标点、数字、繁简、英文大小写、空格、单位和口语词的策略都可能改变分数。

推荐报告字段：总样本数、总参考字/词数、S/D/I、总体 CER/WER、每条样本得分、按场景分层结果、版本和归一化版本、空音频/拒识数量、人工抽检结果。样本平均错误率与语料总编辑数除以总参考单位数是不同聚合口径，应明确选用哪一种。

## 分类与槽位指标

对意图分类报告混淆矩阵、每类 precision/recall/F1、macro 与 micro 汇总。类别不平衡时仅报 accuracy 容易掩盖少数关键意图失败。

槽位可按严格整句匹配，也可按槽位级精确率/召回率/F1。业务场景要单独统计关键槽位正确率、必填槽完整率、值归一化准确率和非法值拦截率。比如“主驾 22 度”中 `zone=driver`、`temperature=22°C` 均须正确，不能只看意图对不对。

## 唤醒与拒识

- **唤醒成功率**：定义语音暴露/目标唤醒机会数、允许时间窗和有效触发条件后计算。多个唤醒短语如何归并需事先规定。
- **误唤醒率**：按非目标暴露时间统计，例如每小时误唤醒次数；明确音乐/对话/静音场景，避免只用“负样本条数”。
- **拒识/误接受**：在低置信、无关请求或非法槽值集合上报告拒识率和错误接受率。
- **打断率**：明确 TTS 播报期间、用户输入类型和停止反馈的判定窗口。

## 时延

先给事件定义，再算差值。例：端到端时延从有效唤醒事件（或音频起点，择一）到业务状态确认事件；另报 final ASR、NLU、业务调用、HMI 首反馈等分段时延。报告中至少包含 p50、p90/p95、最大值、超时比例和样本量。跨设备时钟需记录 NTP/PTP 或其他同步方式与误差；毫秒级结论不能忽略几十毫秒时钟偏移。

## 稳定性与系统指标

可以采集崩溃/ANR、事件丢失、超时、重复执行、恢复成功率、长稳失败间隔、资源使用和设备离线率。要区分系统质量问题与台架/采集器故障；为每个排除样本保留原因，不允许静默删除。

## 对比和趋势

- 固定黄金集、切分逻辑、词表/标签、归一化器和判定器版本。
- 用 paired comparison 比较同一输入在两个版本上的表现，避免数据组成变化造成错觉。
- 对小样本显示样本数和不确定性；不要把 3 条用例的百分数当成稳定总体估计。
- 关键领域按严重度分层，不用总体平均掩盖安全/高频场景退化。
- 设置容忍区间前先建立重复运行的噪声基线，并验证测量系统自身的重复性。

## 参考实现思路

评测管线建议保存两份数据：不可变的原始识别输出和由指定版本归一化器产生的规范化副本。指标计算器接受显式的 `reference`, `hypothesis`, `normalizer_version`, `tokenizer_version`；报告同时输出 aggregate 与逐条对齐，确保差异可审查。`jiwer` 等库可承担编辑距离计算，但文本归一、中文分词和业务等价规则仍需自己定义并版本化。
