# 视觉任务、指标与错误分析

指标必须跟任务输出、数据集标签和业务风险匹配。目标检测、跟踪、分割、车道几何和 DMS 分类回答的问题不同，不能用一个 mAP 或准确率概括全部视觉质量。

## 评测前先冻结口径

报告至少固定：数据集/场景集版本、类别列表、忽略规则、匹配方法、IoU 阈值、置信度阈值、预处理、推理分辨率、模型权重、评估代码版本、样本数、运行硬件和聚合方式。保存逐样本预测与错误明细；指标数字必须可回溯到原帧。

同一图像上改变类别映射、忽略区域、裁切或匹配规则，都会改变分数。先做几个可手算的小例子，验证评估器的 TP/FP/FN 与边界行为，再批量计算。

## 分类：混淆矩阵、Precision、Recall、F1

对于一个指定正类：

```text
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
F1        = 2 · precision · recall / (precision + recall)
```

- **TP**：真实有该目标，模型也报出匹配目标。
- **FP**：真实没有，模型却报出目标。驾驶辅助中可能触发不必要提示/制动链路。
- **FN**：真实存在但模型漏掉。可能使下游系统缺少关键对象。
- **TN**：真实无目标且模型未报。大量背景 TN 会让 accuracy 看起来很高，因此检测任务常更关注 P/R 和 PR 曲线。

阈值降低通常会增加召回，也可能增加误报；需要在需求和下游策略允许的工作点上评估，而不能只挑最高 F1。多类别任务要看每类指标、宏平均/微平均和混淆矩阵，并保留安全关键类别单独结果。

## 目标检测：IoU、匹配与 AP

预测框与标注框的重叠率：

```text
IoU = area(prediction ∩ ground_truth) / area(prediction ∪ ground_truth)
```

一个常用评估步骤是：按类别和预测置信度排序；在指定 IoU 阈值下，将预测与未匹配的真实框进行一对一匹配；匹配成功记 TP，未匹配预测记 FP，未被匹配的真实框记 FN。具体还要规定 ignore/crowd 区域、重复检测、图像边界截断、最大检测数和类别别名处理。

沿置信度阈值扫描得到 precision-recall 曲线，曲线下面积形成 AP；mAP 对类别 AP 求平均。COCO 风格常对多个 IoU 阈值分别算 AP 再平均，因此它与只在 IoU=0.5 计算的 AP50 不同。报告中写清使用哪一种定义和实现。

**手算例子：**某类 10 个真值目标，评估器匹配出 8 个 TP，另外 2 个真值未匹配；模型另报 3 个未匹配框，则 `precision=8/(8+3)=72.7%`，`recall=8/(8+2)=80%`。若一个真值目标被两个预测框重复命中，通常只能有一个记 TP，其余记 FP。这个例子说明框匹配规则会直接影响分子。

### 分层报告建议

按类别、像素尺寸/真实距离、遮挡等级、截断程度、天气、昼夜、相机位置、目标相对速度和 ODD 内外切片。每个切片同时展示样本数、真值数、TP/FP/FN 和指标，避免小样本的 100% 被误读为稳定能力。

## 多目标跟踪

检测器输出每帧目标框；跟踪器还要把同一物体跨帧关联为轨迹。除检测 P/R 外，关注 ID switch（轨迹身份切换）、轨迹中断、重复轨迹、启动/恢复时延和轨迹定位误差。MOTA、IDF1、HOTA 各自组合不同错误项，不应只报一个总分；指标公式和匹配实现要与评估工具版本一起记录。

分层检查遮挡前后重现、交叉汇聚、近距离快速通过、摄像机震动、低帧率、丢帧以及同类目标并行。单帧 mAP 可能完全看不到轨迹抖动和身份错误。

## 分割、车道线和几何任务

- **语义分割：**每像素分类。常用 per-class IoU、mIoU、像素 precision/recall；检查类别不平衡和 ignore label。
- **实例分割：**同时评估实例匹配与掩码重叠，不能用语义分割分数替代实例级结果。
- **车道线：**除像素/折线匹配外，关注车辆坐标下横向位置、曲率、边界偏差、可见性和时间稳定性；远近区域误差意义不同。
- **测距/几何估计：**明确坐标系、单位、真值测量误差和距离切片；可报告绝对误差、RMSE、偏差和分位数。

把平均像素 IoU 直接解释成车辆坐标误差是错误的。对最终功能有用的量通常需要经过标定和坐标变换后单独验证。

## 实时与功能层指标

### 帧率、丢帧与时延

FPS 可按有效完成帧数除以观测时长计算；但平均 FPS 可能掩盖周期性卡顿。记录输入帧时间戳、处理完成时间、排队时间、p50/p95/p99、最大间隔、超时和丢帧率，并说明计时起止点与时钟域。

分开记录摄像头到模型输入、推理、后处理、融合/功能处理和 HMI 反馈时间。同步误差与时间戳重排也属于质量结果。空闲台架上的单次模型推理耗时不能代表多路相机并发和热稳定后的端到端时延。

### 业务功能结果

FCW/AEB、车道保持、泊车或驾驶员监测要定义功能级事件和独立结果证据。感知目标被正确检测、下游功能发出事件、车辆状态改变是不同层级。涉及安全关键功能时按适用的需求、法规、标准和项目安全流程设置判据，不从公开指标页推导通用通过阈值。

## 结果分析与回归比较

新旧版本用同一冻结样本做 paired comparison；逐帧列出新增漏检、误报、类别变化、位置偏差和时延变化。分开“样本/标注变化”“模型变化”“预处理变化”“运行环境变化”，必要时对变化样本人工复核。

错误可按根因候选分组：输入/成像异常、标定/同步、标签歧义、模型漏检/误检、跟踪关联、后处理阈值、算力/时延、功能策略、数据管线或判定器问题。报告应允许“原因未确定”，不要强行把每个失败归入模型。

## 知识点卡片

- **IoU 与 AP 易混点：**IoU 是单个框对匹配重叠度；AP 是扫描置信度得到的曲线面积；mAP 还对类别/阈值做平均。
- **常见误区：**把 AP50 与 COCO mAP 视为同一指标；只展示总 mAP；漏掉数据集和标注版本。
- **先修与练习：**先手算一个 TP/FP/FN 示例，再用评测器复算；对一个阈值变更画 PR 曲线并看置信度边界样本。
- **官方/技术资料：**[COCO detection evaluation](https://cocodataset.org/#detection-eval)、[TorchMetrics Object Detection](https://lightning.ai/docs/torchmetrics/stable/detection/mean_average_precision.html)、[B 站：目标检测 AP/mAP 指标手算与代码](https://search.bilibili.com/all?keyword=%E7%9B%AE%E6%A0%87%E6%A3%80%E6%B5%8B%20AP%20mAP%20%E6%8C%87%E6%A0%87%20%E6%89%8B%E7%AE%97%20%E4%BB%A3%E7%A0%81)。
