# 车载视觉数据集与标注质量

视觉评测的可信度首先取决于“拿什么数据、标签按什么规则、样本怎样切分”。模型分数是数据、标注、预处理、评测器和模型共同作用的结果。数据集文档应让另一位测试人员知道每个样本从哪里来、代表什么条件、允许怎样使用，并能重现相同评测。

## 学习目标

读完后应能设计一份可追溯的数据清单（manifest），区分训练/调参/冻结回归数据，解释目标检测/跟踪/车道线等标注结构，实施基本标签 QA，并从数据切片角度判断指标是否可信。

## 一、样本、帧、片段与数据集版本

- **样本（sample）**：最小评估单位。图像任务常是一帧；跟踪任务通常至少是一个有序片段；环视任务可能需要同一时刻的多路相机帧。
- **片段（clip）**：连续时间窗口，保留帧顺序、时间戳和同步关系。逐帧打散会破坏跟踪、时延和事件评估。
- **数据集版本**：数据文件、标签、切分清单、类别 schema、转换脚本和许可说明的组合。只给一个文件夹名称不能保证版本可复现。
- **冻结回归集**：用于跨版本比较的一组固定样本。访问、修改和调参使用应受控，避免反复适配导致回归结果失去独立性。

数据 manifest 建议至少包含：

| 字段 | 作用 | 示例/注意点 |
|---|---|---|
| `sample_id` | 稳定样本标识 | 不要把可变文件路径当唯一 ID |
| `media_uri`、`sha256` | 定位并校验内容 | 哈希能发现误覆盖或重复内容 |
| `clip_id`、`frame_index`、`timestamp_ns` | 还原时序 | 说明时间戳来源、时钟域和单位 |
| `camera_id`、分辨率、镜头/安装位 | 解释视角 | 脱敏序列号也要保持稳定映射 |
| `vehicle_config`、`isp_version`、`calibration_id` | 追踪成像配置 | 配置变化可能改变几何或像素分布 |
| 场景/目标标签 | 筛选评估切片 | 使用受控词表并注明标注者/规则版本 |
| `annotation_version`、`split` | 追踪标签与用途 | split 例如 train、validation、frozen-regression |
| `license`、采集授权、脱敏状态、保留策略 | 确认合法使用 | 采集地点/人员信息应按最小化原则处理 |

## 二、数据切分与泄漏

训练集用于学习参数；验证集用于选模型、阈值或超参数；测试集用于相对独立的最终评估；冻结回归集用于版本对比。项目可采用不同命名，但必须写清用途和谁能据此调参。

车载视频有强烈的时间和空间相关性。相邻帧几乎相同；同一段道路、同一辆车、同一次天气过程也可能重复出现。若随机按帧切分，近重复样本会同时进入训练与测试，使分数虚高。通常按行程、采集日期、道路/地点、车辆或采集批次分组切分，并用感知哈希、元数据和片段 ID 检查重复。

**数据泄漏检查**应关注：完全相同文件、解码后相同帧、相邻帧跨 split、同一片段裁剪版本跨 split、标签/文件名泄露目标类别、测试集用于反复挑阈值，以及评测脚本读取了训练统计量。

## 三、标注 schema：让标签可计算

### 目标检测框

一个目标通常包含类别、框坐标、实例 ID（若需要跟踪）、遮挡/截断标记、可见性/困难等级和忽略标记。先固定坐标约定：`xyxy` 还是 `xywh`、像素坐标是否从 0 开始、右下边界是否开区间、框以原图还是缩放图为基准。转换程序要有小样本手工校验。

框应覆盖可见目标还是完整物体，要按标注规范说明。部分出画、严重遮挡、反光或无法确定类别时，分别规定截断、遮挡、ignore 和 unknown 的处理，避免标注者凭直觉各自判断。

### 跟踪、车道线和分割

- **跟踪标签**：除每帧框外，需要跨帧稳定的 `track_id`、起止帧、遮挡后是否保留身份、出画/重现的规则。视频片段边界处不能随意复用 ID。
- **车道线标签**：定义车道线类型、可见区间、左右/相邻车道关系、实虚线/边缘语义、图像坐标或车体坐标，以及施工线和旧线的优先级。
- **语义分割**：定义像素类别编码、ignore index、边界抗锯齿处理；确认调色板只是可视化颜色而不是类别 ID。
- **实例分割**：每个对象要同时有类别和独立 mask/实例 ID，约定重叠区域的归属规则。
- **多相机/环视**：标明相机内坐标、同步帧组和跨相机目标关联；不同相机不应因文件排序而误配为同一时刻。

标注定义应配正例、反例和边界例。类别名、属性和忽略规则以机器可读 schema 保存，并通过版本号追踪；改 schema 要说明旧标签如何迁移、历史结果是否可比。

## 四、标注质量控制

1. **格式校验**：文件可解析、图片可解码、坐标有限且在约定范围、类别在枚举表、实例 ID 在片段内唯一。
2. **几何校验**：零面积/极小框、越界框、反转坐标、mask 空洞或尺寸不符；将异常可视化供人工复核。
3. **分布审查**：按类别、场景、相机和 split 统计数量。突然归零或极端不平衡需要解释，不自动视为错误。
4. **双人复核**：对高风险、歧义和随机样本进行独立标注；按类别/属性计算一致性并列出分歧，不只汇总一个百分比。
5. **裁决与回归**：由明确角色按规则裁决；把典型分歧纳入标注手册和标签 QA 套件。
6. **可视化抽样**：固定随机种子抽查容易漏掉的问题，例如小目标、暗部、边缘畸变、跨帧 ID 漂移。

一致率不能不加说明地解释成“真值准确率”。Kappa 等统计量受类别分布影响；框标注的一致性还要看 IoU 分布/边界距离，跟踪标签要看 ID 连续性，分割标签要检查边界和类别混淆。

## 五、数据治理与大模型辅助

数据集卡片应写明目的、适用功能、来源和授权、采集设备、覆盖条件、排除条件、标签 schema、split、已知偏差、脱敏方式、版本、责任人和使用限制。车内外图像可能包含人脸、车牌、位置、路线和驾驶行为；访问控制、脱敏、留存和删除流程要与数据授权一致。

AI 可用于候选标签、模糊样本筛选、近重复检测、属性预标注、失败样本聚类和自然语言检索。自动输出只能作为待审核候选：保存模型/提示词/版本和置信度，抽样人工复核，并对安全关键类别设置更强审核。多模态大模型看起来“理解正确”不等于标签已验证，也不能把模型生成的标签直接写回冻结真值集。

## 常见重难点与错误排查

- **总体指标突然上涨**：先核查测试 split 是否变化、重复帧是否增加、ignore 规则是否改变，再归因模型。
- **模型漏检很多但分数正常**：检查类别映射、空标注、评测阈值、遮挡标签和评估器是否过滤了困难样本。
- **标签复核争议大**：把自然语言定义转成可观察条件和例图；将无法可靠判断的样本标为 ignore/uncertain，并统计其比例。
- **回归结果不可复现**：固定文件哈希、解码器版本、排序、随机种子、模型权重、预处理和评估代码。
- **样本特别多仍覆盖不足**：看切片分布和独立场景数，而非只看帧数；百万相邻帧不等于百万个独立场景。

## 动手练习与验收

选一个有明确许可的小型公开图像集或自建合规样本：设计 JSONL/CSV manifest；定义检测框标签 schema；写脚本校验图片、坐标和类别；按行程/场景组切分；检测重复与近重复；输出各 split 的类别/场景分布；抽取 20 个样本生成可视化质检页。验收时另一位学习者应能据 manifest 重建同一评测输入，并说清数据的用途限制和已知偏差。
