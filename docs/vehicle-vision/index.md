# 车载视觉系统测试与评估

本页是**车载视觉测试的独立领域文档**。它从摄像头成像与数据开始，说明怎样验证视觉感知模型和车端应用的结果。视觉测试与[车载语音测试](/vehicle-voice-testing)分别维护：语音看波形、识别和对话状态；视觉看图像/视频、感知输出和标注对齐。两者共享测试工程方法，但不混用数据、指标和验收门槛。

视觉专题现提供两条互补路线：[车载视觉开发学习路线](/vehicle-vision/development-roadmap)聚焦算法实现、工程化与车端部署；[车载视觉测试学习路线](/vehicle-vision/roadmap)聚焦数据评估、场景覆盖和验证闭环。

## 先界定“车载视觉”包含什么

“车载视觉”不是单一模型。不同功能的输入、输出、风险和验收指标不同，阅读资料和设计用例前先明确被测系统属于哪一类。

| 系统族 | 典型功能 | 常见输出 | 典型验证重点 |
|---|---|---|---|
| 前视 ADAS 感知 | 车辆/行人/骑行者检测、车道线、交通标志/灯识别，为 FCW/AEB/LKA 等提供输入 | 类别、框/轨迹、车道几何、标志状态、置信度 | 距离/速度/光照/遮挡分层，漏检/误检、时序稳定性、感知延迟及下游安全边界 |
| 环视与泊车视觉 | 倒车影像、AVM 环视、泊车辅助/自动泊车的图像感知 | 拼接/鸟瞰图、障碍物/车位、边界/距离 | 相机标定、拼接缝、几何偏差、盲区、小障碍物和低速场景 |
| 舱内视觉 | DMS 驾驶员监测、OMS 乘员/占用监测、姿态或安全带状态识别 | 人脸/关键点/姿态/占用/状态标签 | 眼镜/口罩/逆光/遮挡/座椅姿态、个体差异、隐私和数据授权 |

ADAS 是高级驾驶辅助系统（Advanced Driver Assistance Systems）；AVM 是全景环视监视（Around View Monitor）；DMS 是驾驶员监测系统（Driver Monitoring System）；OMS 是乘员监测系统（Occupant Monitoring System）。这些功能不能因为都使用摄像头就共用一份准确率门槛。

## 视觉系统的数据链路

```text
场景与光照 → 镜头/图像传感器 → ISP 与曝光/HDR → 相机同步/标定
→ 图像或视频帧 → 感知模型 → 跟踪/融合/功能逻辑 → ECU/车辆状态与 HMI
→ 结构化结果、标注对齐、日志与原始图像证据
```

测试前记录注入点。离线图片集只能验证从图像输入开始的模型/软件路径；视频回放能验证时序处理；传感器或台架仿真可以覆盖相机接口、同步和 ECU 运行；道路/场地测试还会引入真实成像和环境变化。报告中写清实际经过与被绕过的组件。

**本知识点学习卡**

- **先修：**图像像素、视频帧、坐标系、基本分类/检测概念。
- **重难点：**区分相机硬件/成像问题、标注问题、感知模型错误和功能决策错误；同一个下游告警失败可能源于不同层。
- **学习文档：**本页的数据链路和[领域案例导航](/vehicle-cases)。
- **B 站学习入口：**[搜索：车载摄像头 ADAS 视觉感知系统架构](https://search.bilibili.com/all?keyword=%E8%BD%A6%E8%BD%BD%E6%91%84%E5%83%8F%E5%A4%B4%20ADAS%20%E8%A7%86%E8%A7%89%E6%84%9F%E7%9F%A5%20%E7%B3%BB%E7%BB%9F%E6%9E%B6%E6%9E%84)。

### 1. 相机成像与标定

先了解分辨率、像素、帧率、曝光时间、增益、动态范围、滚动/全局快门、畸变、HDR、白平衡和 ISP。它们影响进入模型的像素内容，所以不能只检查算法输出。

相机内参描述焦距、主点和畸变；外参描述相机相对车辆或其他传感器的位置与方向。标定结果必须绑定相机安装位置、车辆配置和软件/标定版本。可用棋盘格或项目规定靶标采集图像，测重投影误差及多次标定的稳定性；环视还要检查相机间拼接和地面几何误差。

**重难点：**像素坐标、相机坐标、车体坐标和世界坐标不能混用；标定误差会传导成距离/位置误差。测试要保存坐标系约定、单位、相机 ID、分辨率与时间戳。

**学习资料：**[OpenCV 相机标定文档](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html)；[B 站：相机内外参、畸变与标定](https://search.bilibili.com/all?keyword=%E7%9B%B8%E6%9C%BA%E5%86%85%E5%A4%96%E5%8F%82%20%E7%95%B8%E5%8F%98%20OpenCV%20%E6%A0%87%E5%AE%9A)。

### 2. 视觉任务与指标

先确认模型到底做什么，再选指标。分类关注混淆矩阵、precision/recall/F1；目标检测关注 IoU、AP/mAP 和按类别/距离的漏检、误检；跟踪关注轨迹连续性、ID 切换、IDF1/HOTA 等；语义/实例分割关注 IoU/mIoU；车道线可关注检测率及车道几何偏差。安全相关系统还需看关键场景召回、错误严重度、时延和失效行为。

- **IoU（Intersection over Union）**衡量预测区域与标注区域的重叠，阈值变化会改变 TP/FP 计数。
- **AP/mAP（Average Precision / mean Average Precision）**汇总 precision-recall 曲线或多个类别的 AP；要同时给数据集版本、类别集合和匹配规则。
- **混淆矩阵**显示真实类别与预测类别之间的错误去向，能揭示“把行人认成背景”和“把背景认成行人”这两种代价不同的错误。
- **时延/FPS/丢帧率**描述实时运行能力，必须说明测量边界、输入分辨率、硬件、热状态和统计分位数。

**重难点：**单一 mAP 不能代表道路场景安全性；总体分数可能掩盖远距离、小目标、夜间或遮挡子集的退化。按功能风险、类别、距离、光照和天气分层报告。

**学习资料：**[COCO Detection Evaluation 说明](https://cocodataset.org/#detection-eval)；[B 站：目标检测 IoU AP mAP 评估指标](https://search.bilibili.com/all?keyword=%E7%9B%AE%E6%A0%87%E6%A3%80%E6%B5%8B%20IoU%20AP%20mAP%20%E8%AF%84%E4%BC%B0%E6%8C%87%E6%A0%87)。

### 3. 数据集与标注质量

每个样本至少关联图像/视频哈希、车辆与相机配置、场景标签、采集时间、天气/光照、标注版本、类别定义、数据许可和用途。视频切分要按行程、地点或采集批次隔离，避免相邻帧同时落入训练/测试造成数据泄漏。

标注规范需要定义类别边界、截断/遮挡、忽略区域、困难样本和多目标匹配。用抽样复核、双人标注一致率、类别分布检查、几何边界检查和版本 diff 管理标注质量。训练集、调参集、冻结回归集要有用途隔离。

**重难点：**标签噪声会伪装成模型错误或性能变化；连续视频相邻帧高度相似，随机按帧切分会造成虚高成绩；数据授权、车牌/人脸等隐私内容需要先确定脱敏和访问策略。

**学习资料：**[CVAT 标注文档](https://docs.cvat.ai/docs/)；[B 站：目标检测数据集标注规范与数据泄漏](https://search.bilibili.com/all?keyword=%E7%9B%AE%E6%A0%87%E6%A3%80%E6%B5%8B%20%E6%95%B0%E6%8D%AE%E9%9B%86%E6%A0%87%E6%B3%A8%20%E8%A7%84%E8%8C%83%20%E6%95%B0%E6%8D%AE%E6%B3%84%E6%BC%8F)。

### 4. 场景覆盖与边界条件

使用场景矩阵组合道路类型、目标类别、距离/尺度、相对速度、遮挡、天气、光照、相机污损、曝光、逆光、隧道出入口、夜间反光、LED 闪烁和施工/临时标识。优先覆盖产品 ODD（Operational Design Domain，运行设计域）内高风险场景，并保留 ODD 边界和域外输入的安全降级检查。

场景测试不要只按“晴天/雨天”粗分。要记录可复现因素，例如目标像素尺寸、遮挡比例、光照方向、雨滴/污渍位置、道路曲率、相机帧率和时间同步条件。合成或仿真场景适合补充覆盖，但应与实采/场地数据的分布差异单独说明。

**重难点：**长尾场景样本少，随机抽样很难稳定复现；仿真画面逼真不代表传感器噪声、动态范围和模型域偏移真实。通过固定场景 ID、输入哈希和参数版本管理复现。

**学习资料：**[ASAM OpenSCENARIO](https://www.asam.net/standards/detail/openscenario/)；[B 站：自动驾驶场景库 ODD 长尾场景测试](https://search.bilibili.com/all?keyword=%E8%87%AA%E5%8A%A8%E9%A9%BE%E9%A9%B6%20ODD%20%E9%95%BF%E5%B0%BE%E5%9C%BA%E6%99%AF%20%E4%BB%BF%E7%9C%9F%E6%B5%8B%E8%AF%95)。

### 5. 测试分层与证据闭环

| 层级 | 主要目的 | 常见证据 |
|---|---|---|
| 离线图像/视频回归 | 快速比较模型、标注和阈值变更 | 输入哈希、预测结果、标注版本、分层指标 |
| 仿真/传感器回放 | 检查时序、接口、场景和功能链路 | 帧时间戳、传感器配置、模型输出、功能事件 |
| ECU/台架测试 | 检查目标硬件运行、实时性和资源约束 | FPS、时延、丢帧、资源/温度、日志与版本 |
| 场地/道路验证 | 检查真实成像和系统级行为 | 传感器记录、车辆状态、功能/HMI 事件及安全记录 |

每个结果都带模型/固件/标定版本、输入与标注版本、设备配置、运行参数和证据地址。算法框架报告不能代替车端实时性和功能行为验证；道路测试也不能因环境难复现而不保存原始数据。

**重难点：**输入回放是否经过 ISP、同步、感知 ECU 和下游功能路径必须讲清；离线模型指标通过，不等于 ECU 上实时运行通过，更不等于整车功能安全通过。

**学习资料：**[OpenMMLab MMEngine Evaluation](https://mmengine.readthedocs.io/en/latest/advanced_tutorials/evaluation.html)；[B 站：自动驾驶感知算法离线评测与车端部署测试](https://search.bilibili.com/all?keyword=%E8%87%AA%E5%8A%A8%E9%A9%BE%E9%A9%B6%E6%84%9F%E7%9F%A5%20%E7%A6%BB%E7%BA%BF%E8%AF%84%E6%B5%8B%20%E8%BD%A6%E7%AB%AF%E9%83%A8%E7%BD%B2%E6%B5%8B%E8%AF%95)。

## 推荐的最小实践项目

选取具有明确许可的公开图像/视频子集或自采且已授权的数据，构建一个目标检测评估小项目：

1. 冻结数据集、标签 schema、模型权重、推理参数和评估代码版本。
2. 校验图像可读性、分辨率、重复文件、标签范围和训练/测试泄漏。
3. 输出逐样本预测与错误可视化，计算总体及按类别/目标尺寸分层的 precision、recall 和 AP。
4. 建立一个冻结回归集，用新旧模型作配对比较；列出新增漏检、误检和不确定样本。
5. 把数据许可、硬件需求、运行命令、结果、局限和失败样本一起写入报告。

练习通过标准是另一位学习者能在干净环境重跑并得到相同预测/指标，能从汇总分数追溯到单帧和标注。此离线练习不声称覆盖车端摄像头、实时 ECU 或道路功能验收。

## 安全、隐私与工程边界

- 道路采集/试验依照项目授权、场地规则和车辆安全流程；模型测试不得绕过整车安全联锁。
- 图像可能包含人脸、车牌、住址和位置轨迹。采集前说明用途和权限，按要求脱敏、最小化访问并设置保留期限。
- 传感器回放、仿真、SIL/HIL 和实车运行的覆盖范围分别记录，不要用一个“通过”状态混写。
- 视觉指标不能单独证明车辆功能安全或法规符合性；适用的标准、法规和功能安全要求需由项目确认并按正式文件验证。
