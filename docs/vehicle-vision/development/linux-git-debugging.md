# Linux、Git 与调试工具

视觉开发环境通常运行在 Linux 主机、容器或目标 ECU 上。应能检查进程、资源、库依赖和日志，并通过 Git 让代码变化可追溯。

## Linux 基础

理解文件路径、权限、用户/组、进程、线程、信号、环境变量和动态库加载。检查可执行文件架构及依赖库，区分“文件不存在”“权限不足”“库版本不匹配”和“设备不可用”等不同故障。shell 脚本中的变量、退出码、管道和错误处理要明确。

## Git 协作

用小而聚焦的提交表达一项变化；提交前检查 diff、生成文件和敏感数据。分支、合并、rebase 和冲突解决应保留历史语义。模型权重或大体积数据若不能放普通 Git，应记录外部制品的 URI、版本和哈希。

## 调试工具的使用顺序

1. **日志：**先确认程序版本、输入 ID、阶段、时间戳、错误码和资源状态。
2. **调试器：**崩溃时查看调用栈、局部变量和线程；死锁时检查所有线程的栈与锁等待。
3. **Sanitizer：**开发阶段发现越界、释放后使用、数据竞争或泄漏。
4. **系统监控：**观察 CPU、内存、线程、文件描述符、设备利用率和温度。
5. **Profiler：**用采样或平台工具确认热点，避免凭感觉优化。

采集证据时保存命令、程序版本、输入和复现步骤。若日志包含图像路径、车辆位置或乘员信息，按项目隐私策略脱敏。

## 常见问题

- `LD_LIBRARY_PATH` 或设备环境变量只在交互终端设置，服务启动时没有继承。
- 用 `kill -9` 结束进程后丢失退出前日志和资源状态。
- profiler 的 Debug 数据被当成 Release 性能结论。
- Git 中提交本地数据、密钥或无版本来源的模型文件。

## 练习与完成标准

对一个故意触发崩溃的图像程序，使用调用栈定位错误；对一个内存增长样例，结合进程资源和 sanitizer 定位问题。将修复、构建命令和复现方法提交到 Git，并能从 commit 找到对应输入版本。
