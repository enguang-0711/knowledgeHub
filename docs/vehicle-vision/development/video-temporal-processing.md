# 视频时序与流式处理

将图像算法放入视频流后，时间戳、队列和状态管理会决定输出是否及时、连续和正确。高吞吐不一定代表低延迟：队列过长时，每帧都可能处理成功，却始终落后于真实场景。

## 帧身份和时间

为帧保留相机 ID、采集时间戳、帧序号、输入版本和处理阶段时间。区分采集、接收、推理开始/结束和发布时刻。检查重复帧、乱序、时间跳变、帧率抖动和丢帧。

## 队列和背压

生产者/消费者速率不匹配时要定义策略：阻塞生产者、丢弃最旧帧、丢弃最新帧或降低处理频率。实时感知常更关注新鲜数据，但具体策略要看功能契约。队列必须有容量限制，并记录丢弃原因、队列深度和帧数据年龄。

异步处理应确保帧 ID、标定和车辆状态与图像属于同一时间点。并行推理可能打乱完成顺序，输出端应依据帧时间和业务定义进行排序或丢弃过期结果。

## 时序算法状态

跟踪、平滑和事件检测需要明确状态初始化、超时、重置和恢复条件。长时间无观测时，不能无限外推旧结果。帧间间隔变化时，速度估计和滤波参数应使用真实时间差，而非假设固定帧率。

## 常见问题

- 以接收时刻作为采集时间，掩盖传输延迟。
- 队列不设上限，内存和数据年龄持续增长。
- 输出只按处理完成顺序写入，造成时序乱序。
- 帧丢失后沿用跟踪状态，没有记录状态年龄和置信度变化。

## 练习与完成标准

构造一个视频回放服务，统计每阶段延迟、p50/p95 数据年龄、帧丢失、乱序和队列深度。注入处理变慢、帧间隔变化和相机重连，验证系统按契约处理状态和恢复。
