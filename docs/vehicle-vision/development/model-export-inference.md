# 模型导出与推理部署

把训练模型部署到目标平台，需保持模型结构、输入预处理、后处理和运行时配置一致。导出成功只说明文件生成，不能证明数值、性能或系统行为正确。

## 部署流水线

1. 固定训练代码、权重、类别 schema、输入尺寸和预处理配置。
2. 导出到 ONNX 或目标推理 SDK 支持的格式，记录输入输出名称、shape、dtype 和动态维度。
3. 用目标运行时加载模型，检查算子支持、编译日志和资源需求。
4. 对同一批样本比较原框架与部署引擎的中间张量/最终输出。
5. 接入实际图像缓冲区、后处理、错误码和服务生命周期。
6. 在目标硬件执行功能回归、端到端性能和长时稳定性检查。

## 数值一致性

分类可比较 logits 或概率；检测/分割要比较候选张量及后处理结果。定义绝对/相对误差阈值，并考虑浮点实现差异。若只比较最终类别，可能掩盖接近阈值时的重大分数偏移。逐步排查输入张量、算子输出、精度模式和坐标后处理。

## 运行时集成

处理输入输出缓冲区、内存布局、线程/流、同步和资源释放。连续运行时要防止重复创建上下文或缓冲区造成内存增长。错误必须可观测；推理失败时不能静默返回上一帧结果。

## 平台选择

ONNX 可作交换格式，TensorRT、OpenVINO 或厂商 SDK 提供特定硬件优化。选择取决于 ECU、算子覆盖、编译工具链和维护策略。记录 SDK、驱动、固件、编译器和模型转换器版本；升级后重新验证。

## 练习与完成标准

将一个模型导出并运行在目标或明确标记的模拟平台；用固定样本配对比较输出，报告误差、未支持算子、输入约束、运行命令和版本。至少定位一个人为制造的预处理/后处理不一致。
