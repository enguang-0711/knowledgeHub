# 视觉开发中的 C++ 资源生命周期

## 生命周期和所有权

图像缓冲、GPU/NPU 句柄、文件、线程和网络资源需要明确创建者、所有者、释放时机和异常路径。优先使用 RAII、智能指针和值语义表达所有权，避免裸指针与隐式共享造成泄漏、双重释放或悬空引用。

## 图像缓冲区

图像不一定连续；每行 stride、像素格式、对齐和内存域都会影响索引。零拷贝缓冲需明确生产/消费完成事件，不能在硬件仍使用时复用。多线程读写共享图像时定义不可变阶段或同步机制。

## 实时和性能

帧处理热路径避免不必要分配、深拷贝和锁竞争，但先测量瓶颈再优化。缓冲池要限制容量并定义背压/丢帧策略；析构和错误清理不能阻塞实时回调。

## 练习与验收

实现一个带 stride 的图像 buffer wrapper，覆盖移动、异常退出和多线程消费者生命周期。用 AddressSanitizer/线程检查器验证无越界、泄漏和数据竞争。

## 所有权设计与异常路径

把图像缓冲封装为带尺寸、格式、stride、内存域和所有者信息的对象；只读消费者使用明确的借用视图，异步任务必须持有足够长的所有权。零拷贝并不等于无生命周期约束：设备完成事件之前不能复用缓冲。

用 RAII 管理文件、锁、推理上下文和设备句柄；队列必须设上限，并说明满队列时丢最旧帧、阻塞还是拒绝。析构流程先停止生产、通知消费者、等待任务结束，再释放底层设备资源。

**验收产物：**为正常退出、构造失败、推理超时和取消任务分别写测试；用 ASan/TSan 或平台等价工具检查越界、悬空视图、泄漏和竞争，并记录长时运行的缓冲池容量。
