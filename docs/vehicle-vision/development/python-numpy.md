# Python、NumPy 与视觉数据处理

Python 常用于数据检查、实验、训练、评估和工具脚本。视觉开发中最常见的脚本错误来自数组维度、通道顺序、数据类型和隐式复制，而不是复杂语法。

## NumPy 数组核心概念

- **shape：**确认数组代表 `H×W×C` 还是 `C×H×W`，视频还可能有时间和 batch 维度。
- **dtype 和数值范围：**`uint8` 常表示 0–255；浮点输入可能要求 0–1 或归一化后范围。不要只转换类型而忘记缩放。
- **stride 与连续性：**裁剪、转置可能生成非连续视图；下游库可能拒绝，也可能悄悄复制。
- **view 与 copy：**切片常共享底层内存，原数组被修改会影响视图。需要独立快照时要显式复制。
- **广播和向量化：**用于高效处理数组，但要确认广播轴符合预期；形状对齐错误有时会产生可运行但错误的结果。

## 数据输入与可复现脚本

把数据读取、参数解析、处理、统计和输出分开。脚本应通过命令行接收输入路径、配置和输出目录；退出码表示成功或失败；日志记录样本数和跳过原因。不要通过硬编码本机路径或手工改变量来运行关键实验。

图像读取后先检查解码是否成功，再检查宽高、通道、位深和像素范围。视频处理需报告实际读取帧数、时间戳来源和帧间隔；损坏帧应被统计，而不是静默跳过。

## 文件和数据格式

使用 JSON/YAML 等结构化配置描述模型参数、标签 schema 和预处理。对大规模样本建立 manifest，记录相对路径、哈希、尺寸、标签版本、来源许可和切分。图像、标注和模型输出应能通过稳定 ID 配对。

## 常见问题

- OpenCV 读入 BGR 后直接当 RGB 送入模型。
- 将 `uint8` 转为 `float32`，却没有把 0–255 缩放到模型期望的范围。
- 对图像做转置后忽略非连续内存，导致接口报错或额外复制。
- 脚本只打印汇总分数，不保存逐样本失败项和参数版本。

## 练习与完成标准

写一个数据审计脚本，扫描图像和标签，输出损坏文件、尺寸/通道分布、空标注、越界框和重复哈希清单。给脚本补参数、退出码和可复现示例；运行两次应得到相同的样本统计。
