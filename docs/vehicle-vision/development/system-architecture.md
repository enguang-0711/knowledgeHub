# 车载视觉系统架构

## 端到端链路

常见链路为图像传感器、SerDes/CSI、ISP、图像缓冲、预处理、模型推理、后处理、跟踪/融合、业务接口和记录/显示。架构图要标明每一步的数据格式、分辨率、时钟域、内存位置、线程/进程和硬件加速器。

## 模块边界

接口定义帧 ID、时间戳、相机 ID、坐标系、图像 stride、像素格式、缓冲区所有权和无效状态。生产者与消费者约定队列容量、背压或丢帧策略；异步处理必须能把结果关联回输入帧。

## 实时与资源预算

从曝光/采集到输出业务结果拆解时延，识别同步等待、内存复制、颜色转换和 NPU 排队开销。管理内存带宽、温度、功耗、CPU/NPU 使用率和多路相机并发。平均帧率不能替代长尾延迟和丢帧统计。

## 降级和诊断

定义摄像头掉线、帧冻结、曝光异常、标定无效、模型加载失败、队列溢出和推理超时的可观察状态。每个输出可追踪输入帧和版本，便于判定算法错误还是数据链路错误。

## 练习与验收

画出双摄像头实时检测架构，标注内存和时间戳流向。注入一路断流和推理变慢，说明系统如何识别、隔离并向业务层报告。

## 组件边界与接口审查

对相机接入、预处理、推理、后处理/跟踪、消息输出和下游消费者逐一列出输入输出 schema、线程模型、时间戳、坐标系、缓冲所有权及错误码。标出同步等待点和队列容量，确认端到端预算不会因多个模块各自“满足局部时延”而超标。

比较集中式与分模块、CPU/GPU/NPU、批处理与逐帧执行等方案时，同时估算延迟、内存、功耗、故障隔离和维护成本。数据新鲜度必须进入契约；格式正确但已过期的目标应被拒绝或标记。

**验收产物：**维护系统数据流图、接口版本表、依赖/资源预算和失效状态图。通过断流、超时、乱序和资源不足演练验证架构图中的故障路径与实际日志一致。
