# 视觉数据集工程

## 数据版本

每张图像或视频片段应有稳定 ID、来源、采集时间、车辆/相机配置、天气光照、地点/场景、授权和哈希。数据版本应可重建，训练运行记录所用清单、预处理配置和排除规则。

## 切分与代表性

按驾驶片段、车辆、地点、日期或采集批次切分，避免相邻视频帧同时进入训练和测试。分布要覆盖目标 ODD，并保留困难样本和域外样本的单独集合；随机逐帧切分通常会高估泛化。

## 数据质量检查

检查解码失败、重复帧、模糊/曝光异常、时间戳缺失、相机配置不匹配和标签引用缺失。自动去重可用文件哈希与感知哈希组合，并保留重复关系，不能盲目删除合法的相似场景。

## 练习与验收

构建含视频片段的 manifest 和哈希校验器，按片段分割数据集，报告场景分布和潜在泄漏。换机器后仍能从同一清单重建完全一致的样本集合。

## 数据集发布操作

定义稳定 sample ID 与 manifest schema，将原始文件、标签、场景元数据和授权状态分开保存；manifest 记录文件哈希、帧范围、相机/车辆配置、采集批次、标签版本及排除原因。导入时先检查解码、尺寸、时间戳、重复和元数据完整性。

切分应以行程/录制会话等相关群组为单位，再检查感知哈希近重复和跨集合相邻片段；所有过滤条件和随机种子纳入数据版本。训练代码只读取不可变清单，不能在运行时随机从“最新目录”取数据。

**验收产物：**生成数据卡、清单哈希、场景分布表、切分泄漏报告和可重复构建命令；在另一工作目录重建后，样本 ID 与顺序应一致，新增/删除样本能通过 manifest diff 解释。
