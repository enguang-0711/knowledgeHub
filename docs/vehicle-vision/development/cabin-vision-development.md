# 舱内 DMS/OMS 视觉开发

舱内 DMS（驾驶员监测）和 OMS（乘员监测）使用摄像头估计驾驶员/乘员位置、姿态或状态。算法会受到座舱布置、红外成像、遮挡和个体差异影响，数据授权与隐私保护贯穿整个开发流程。

## 典型算法链路

```text
可见光/红外图像 → 人脸/人体与座位定位 → 关键点/姿态/视线等特征
→ 时序状态估计 → 事件和有效性输出
```

区分单帧模型输出和持续事件定义。疲劳或分心状态往往需要时间窗口和状态机；事件开始/结束、置信度、无效状态和复位条件应有明确接口。

## 关键知识点

- **座位和人员关联：**明确多人场景下人员与座位的映射及上车/离车状态。
- **关键点与姿态：**定义点位 schema、遮挡和可见性，统一头部/视线坐标系及角度单位。
- **红外与补光：**检查眼镜反光、补光不均、过曝、夜间噪声和不同传感器响应。
- **个体与座舱变化：**覆盖不同体型、肤色、眼镜/口罩、座椅位置、方向盘和手部遮挡。
- **时序决策：**以连续观测判断事件，避免单帧噪声触发频繁状态跳变。
- **隐私工程：**明确采集授权、用途、脱敏、访问控制、最小保留和删除流程。

## 开发和评估注意

数据切分应避免同一乘员、座舱配置或连续视频同时泄漏到训练和测试。按传感器类型、人群、遮挡和昼夜做分层分析；总体分数不足以反映不同人群间的表现。事件级指标应定义事件窗口和时间容差。

## 练习与完成标准

选择一个低风险状态估计任务，搭建关键点/分类与时间窗口原型；可视化每帧置信度和最终事件区间，注入遮挡或短时丢帧观察状态机。数据使用需有明确许可，交付中不包含不必要的原始人脸信息。
