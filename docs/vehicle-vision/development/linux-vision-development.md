# Linux 视觉开发环境

## 目标平台

理解进程、线程、权限、文件系统、动态库、设备节点和系统服务。车端视觉还涉及摄像头/视频节点、GPU/NPU 驱动、内存映射和设备温度；不同 SoC 的接口以平台文档为准。

## 工具链

熟悉交叉编译器、sysroot、ABI、环境变量、部署方式和远端日志。运行失败先检查可执行架构、动态库、设备权限和依赖版本，再检查模型/输入问题。

## 性能观测

使用系统 profiler、日志和资源监控查看 CPU、内存、线程、I/O、温度和加速器队列。生产设备调试遵守权限和安全流程，不修改未授权固件或系统配置。

## 练习与验收

将小型视频推理程序部署到模拟目标环境，记录启动、库加载、输入读取和资源使用。按文档在另一干净设备/容器复现。

## 目标机问题定位路径

部署前记录 CPU 架构、ABI、内核、驱动、推理 SDK、系统库与设备节点权限；安装包应携带明确版本的模型、配置和类别表。出现启动失败时，先确认二进制架构与动态库解析，再检查相机/GPU/NPU 权限，最后验证模型与输入，不要一开始就归因于算法。

运行中用结构化日志串起 frame ID、线程、时间戳、错误码和资源水位；采集 CPU、内存、文件描述符、设备利用率及温度趋势。目标机上的测量需区分调试构建和发布构建，并保留执行命令与环境。

**验收产物：**提供干净设备/容器部署说明、依赖清单和故障复现记录。测试权限不足、库缺失、设备不可用和模型路径错误时，系统要给出不同且可操作的诊断。
