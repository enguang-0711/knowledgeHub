# 车载视觉开发学习路线

这条路线面向希望从视觉算法学习走到车端落地的开发者，覆盖基础编程、图像与几何、视觉算法、深度学习、数据训练、模型部署和系统集成。本文只组织开发知识；测试路线和专题文档单独维护，内容总览见[车载视觉专题](/vehicle-vision/)。

建议每周投入 8–12 小时，按阶段产物推进。已有基础的学习者可以压缩熟悉阶段，但每个阶段都应留下可运行的代码、实验记录或设计说明。车载视觉不是单一算法方向，尽早选择前视 ADAS、环视/泊车或舱内 DMS/OMS 作为主线。

## 路线总览

| 阶段 | 建议时间 | 核心主题 | 阶段产物 |
|---|---:|---|---|
| 0 | 1 周 | 选择功能、读懂系统链路 | 一张系统图和一份需求/约束清单 |
| 1 | 2–3 周 | C++、Python、Linux 与数值基础 | 可构建的图像处理小程序 |
| 2 | 2 周 | 图像处理、相机模型与坐标变换 | 标定和几何验证实验 |
| 3 | 2 周 | 经典视觉与视频时序 | 可复现的特征、光流或几何小项目 |
| 4 | 3–4 周 | 深度学习与视觉任务 | 一个有训练、评估和错误分析的模型基线 |
| 5 | 2–3 周 | 选择 ADAS、环视或舱内视觉方向 | 面向功能需求的算法原型 |
| 6 | 2–3 周 | 模型导出、端侧部署与性能优化 | 目标设备上的可测量推理程序 |
| 7 | 持续 | 系统集成、可靠性与持续迭代 | 版本化、可回归的端到端功能 |

时间是学习安排参考，不代表完成后即可独立负责量产系统。实际项目还需要遵循产品需求、车规平台、功能安全和数据治理流程。

## 阶段 0：从功能需求和系统链路开始

先确定主线和算法在整车中的位置：

| 主线 | 常见输入 | 代表性输出 | 主要工程约束 |
|---|---|---|---|
| 前视 ADAS | 单目或多目视频、标定参数 | 目标、车道线、交通标志/灯、深度或运动信息 | 远距离小目标、低延迟、时序稳定、恶劣成像 |
| 环视与泊车 | 多路鱼眼相机、相机标定、车辆状态 | 环视/鸟瞰图、车位、障碍物、边界 | 多相机同步、畸变校正、拼接几何和近场盲区 |
| 舱内 DMS/OMS | 红外或可见光图像、座舱配置 | 人脸/关键点/姿态、驾驶员状态、占用状态 | 夜间补光、遮挡、个体差异、隐私与设备差异 |

把功能拆成“传感器输入 → 预处理 → 模型/算法 → 时序或几何后处理 → 功能接口 → HMI/车辆状态”，标出每一步的数据格式、坐标系、时间戳、运行平台和延迟预算。这个系统图会成为后续设计和调试的索引。

| 知识点 | 要弄清楚的问题 | 建议产物 |
|---|---|---|
| 需求到算法任务 | 输入场景、目标对象、输出定义和使用方是什么？输出是框、车道几何、状态标签还是鸟瞰图？ | 输入/输出契约和术语表 |
| 数据链路 | 图像从传感器经过哪些驱动、ISP、解码和预处理？训练和部署各自从哪里取数据？ | 数据流图，注明每段的数据格式 |
| 系统边界 | 算法负责到哪里，跟踪、融合、功能逻辑和 HMI 由谁负责？ | 模块边界图和依赖清单 |
| 时序与资源 | 输入频率、处理截止时间、并发相机数、内存/算力限制是什么？延迟从哪里开始计时？ | 延迟预算和资源约束表 |
| 失效行为 | 相机断流、图像无效、标定缺失或算法超时时，调用方如何识别并处理？ | 异常状态与降级行为清单 |

**工程判断：**需求中“识别准确”不足以直接指导实现。至少要明确对象定义、坐标系、更新频率、时效窗口、有效性标志、置信度含义和下游使用方式。不同模块若各自解释这些字段，会在集成时产生隐蔽错误。

**练习与验收：**选一个明确功能，写出输入、输出、运行频率、目标硬件、可接受失效行为和待确认约束；为每个输出找到可以检查的可视化或日志。

**开发知识点：**[前视 ADAS 感知开发](./adas-perception-development) · [环视与泊车视觉开发](./surround-view-development) · [舱内 DMS/OMS 视觉开发](./cabin-vision-development)

**知识点文档：**[功能需求与视觉系统架构](/vehicle-vision/development/system-architecture-and-requirements)

## 阶段 1：编程、数学和开发环境

车端算法岗位通常需要同时理解模型代码和运行时工程。按“能读懂、能修改、能定位问题”的目标建立以下能力：

| 知识点 | 重点内容 | 达到的能力 |
|---|---|---|
| C++ 与资源管理 | C++17 常用语法、值类别、引用、RAII、智能指针、容器、模板基础、异常边界；理解对象所有权、生命周期和拷贝/移动成本 | 能写清晰的多文件模块，避免悬空引用、重复释放和不必要的大块图像复制 |
| 并发与内存 | 线程、互斥锁、条件变量、原子变量、生产者/消费者、队列长度和背压；理解缓存、对齐及 CPU/GPU 间数据搬运 | 能解释并定位数据竞争、队列堆积、帧延迟上升和内存增长 |
| Python 与 NumPy | ndarray 的 shape、dtype、stride、广播、索引、view/copy；文件、JSON/YAML 和命令行参数处理 | 能编写可复跑的数据检查、转换、训练和评估工具，并识别隐式复制或通道顺序错误 |
| Linux 工具 | shell、进程/线程、权限、信号、动态库、环境变量、日志、gdb、AddressSanitizer 和 perf 基础 | 能从崩溃栈、日志和资源曲线缩小问题范围，而不只依赖 IDE 单步调试 |
| 构建与依赖 | CMake target、头文件/库依赖、编译选项、Debug/Release、交叉编译概念、依赖锁定 | 能在干净环境重建程序，并区分编译期、链接期和运行期错误 |
| Git 与协作 | 分支、提交、diff、冲突解决、代码审查、版本标签和回滚 | 能让代码改动可审查、可定位、可恢复 |
| 线性代数 | 向量、矩阵乘法、转置、逆矩阵、齐次坐标、特征值/奇异值的直观含义 | 能检查坐标变换的输入输出维数、方向、单位与数值稳定性 |
| 概率与统计 | 条件概率、均值/方差、分位数、抽样偏差、置信区间的基本概念 | 能理解数据分布变化、指标波动和小样本结论的限制 |
| 微积分与优化 | 导数、链式法则、梯度、学习率和梯度下降 | 能读懂反向传播和损失优化过程，排查不收敛、梯度异常和过拟合 |

不必在进入实践前学完所有数学证明，但每个公式都应能解释变量、维度、单位及其对代码结果的影响。

**重难点：**能跑 Python 模型不等于能把功能放进实时 C++ 服务；内存复制、线程安全、图像缓冲区生命周期和依赖兼容性都会影响端侧结果。

**练习与验收：**编写一个 C++ 命令行程序，读取图像或视频、执行缩放和颜色转换并输出结果；再写 Python 脚本对输出做尺寸、通道和像素范围检查。为工程补上 CMake 构建、参数校验、错误日志、至少一个边界用例和干净环境构建说明。验收时能解释图像对象的所有权、stride 和是否发生了数据拷贝。

## 阶段 2：图像处理、成像与几何

这一阶段要把“图像像素是什么”和“像素代表什么空间位置”分开学习。前者属于成像与图像处理，后者属于相机几何和标定。

| 知识点 | 重点内容 | 常见错误或检查项 |
|---|---|---|
| 图像存储 | HWC/CHW、stride、连续内存、BGR/RGB、灰度、alpha 通道、uint8/float、数值范围 | shape 正确但通道错序；把 0–255 与 0–1 输入混用；忽略行跨度 |
| 视频像素格式 | RGB/BGR 与 YUV 族、NV12 等半平面格式、位深、色度抽样和解码 | 色偏、亮度范围不一致、UV 平面偏移错误；记录摄像头/解码输出的实际格式 |
| 图像变换 | resize、crop、padding、仿射变换、透视变换、插值方法和像素中心约定 | 模型输出坐标未映射回原图；训练与推理使用不同插值、padding 或舍入规则 |
| 图像增强 | 直方图、亮度/对比度、滤波、边缘、形态学、去噪和锐化 | 增强改变了目标边界或纹理；增强参数不能代表真实 ISP 行为 |
| 成像基础 | 曝光时间、增益、白平衡、动态范围、HDR、快门类型、镜头污损和运动模糊 | 只调模型阈值来掩盖曝光/清晰度问题；没有保留原始采集配置 |
| 相机模型 | 针孔模型、径向/切向畸变、鱼眼模型、内参矩阵和畸变参数 | 把鱼眼相机按普通针孔模型处理；图像分辨率变更后仍沿用未换算的内参 |
| 坐标系 | 像素、相机、车体、世界/地图坐标；右手/左手约定、轴方向和长度单位 | 坐标轴方向、角度单位或矩阵相乘次序不一致 |
| 外参与变换 | 旋转和平移、齐次变换、变换链和逆变换 | 把“相机到车体”与“车体到相机”混淆；把旋转和平移作用于错误坐标系 |
| 投影与反投影 | 3D 点投影到图像、已知深度下的反投影、畸变校正和有效视场 | 忘记齐次归一化；忽略深度为零/负值或图像边界外点 |
| 标定与验证 | 标定数据覆盖、重投影误差、残差分布、参数稳定性和版本绑定 | 只看一个总体误差；棋盘格覆盖不足或配置/镜头/安装发生变化 |
| 相机时序 | 时间戳来源、相机间同步、帧率抖动、滚动快门和运动状态对齐 | 用接收时间代替采集时间；多相机帧错配却归因为算法波动 |

建议建立统一的图像预处理契约，明确输入尺寸、颜色空间、数值范围、resize/pad 方式、归一化参数和输出坐标映射。训练代码和端侧代码都按同一份契约实现并用固定样例逐项比对。

**重难点：**坐标系、单位、图像 resize/padding 规则和时间戳必须一致。训练预处理与车端预处理只要有细微差别，就可能产生难以解释的精度退化。环视还需要理解鱼眼成像和多相机几何，不能直接套用普通针孔模型假设。

**练习与验收：**用公开样例或授权数据完成一次相机标定与去畸变；将若干 3D 点投影到图像，再将图像点反投影到指定深度，验证坐标和单位。额外构造分辨率变化、边缘点、空图像和格式错误等用例。记录相机模型、输入分辨率、标定参数、误差分布和可视化，并说明适用的安装/镜头配置。

**学习资料：**[OpenCV 相机标定教程](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html) · [OpenCV 图像处理教程](https://docs.opencv.org/4.x/d6/d00/tutorial_py_root.html)

**知识点文档：**[相机成像与镜头模型](/vehicle-vision/development/camera-imaging-and-lens-models) · [坐标变换、标定与时间同步](/vehicle-vision/development/camera-geometry-calibration-sync)

**知识点文档：**[图像格式与预处理](/vehicle-vision/development/image-formats-preprocessing) · [相机成像与镜头模型](/vehicle-vision/development/camera-imaging-and-lens-models) · [坐标变换、标定与时间同步](/vehicle-vision/development/camera-geometry-calibration-sync)

## 阶段 3：经典视觉与视频处理

学习滤波、阈值、边缘、角点与局部特征、透视变换、单应性、光流、背景建模和图像金字塔。理解单帧处理与视频处理的差别：帧间运动、短时遮挡、抖动、曝光变化和处理延迟都可能改变最终功能行为。

| 知识点 | 需要理解的内容 | 典型用途/边界 |
|---|---|---|
| 滤波与图像金字塔 | 卷积、平滑、锐化、下采样/上采样、多尺度处理 | 去噪和多尺度分析；滤波会平滑小目标或边缘，需检查副作用 |
| 阈值与形态学 | 固定/自适应阈值、腐蚀、膨胀、开闭操作 | 二值化和区域清理；受光照与参数影响，通常适合受控子问题 |
| 边缘和角点 | 梯度、边缘响应、角点检测和非极大值抑制的直观含义 | 结构提取、跟踪点选择；纹理弱、重复纹理和运动模糊会降低稳定性 |
| 局部特征匹配 | 描述子、距离度量、匹配筛选和几何一致性 | 图像配准、拼接和定位；匹配数量多不等于匹配正确 |
| 几何变换 | 仿射变换、单应性、透视校正、RANSAC 外点剔除 | 平面或近似平面映射；普通单应性不能描述任意 3D 场景的视差 |
| 光流与跟踪 | 稀疏/稠密光流、金字塔搜索、特征点跨帧关联 | 运动估计和短期跟踪；快速运动、遮挡、弱纹理、曝光变化会失效 |
| 视频时序 | 帧时间戳、丢帧、重复帧、队列延迟、状态重置和短期平滑 | 避免以旧帧结果冒充当前结果；时序状态须明确初始化和清理条件 |
| 图像质量 | 清晰度、过曝/欠曝、噪声、污损、遮挡、颜色异常 | 诊断感知退化来源；质量分数只用于定义清楚的用途，不能代替功能判定 |

经典视觉的价值在于掌握几何、像素变化和误差传播的直觉。工程中可以将传统方法与学习方法组合，但需要用具体场景验证组合后的稳定性和延迟。

经典方法依然适用于标定、图像增强、几何变换、质量检查和部分低成本任务。学习它们也能帮助定位深度模型前后的预处理问题，不必把所有视觉问题都直接交给神经网络。

**练习与验收：**选取一段合法来源的视频，实现特征跟踪或稀疏光流；记录失败帧，并区分快速运动、弱纹理、遮挡和曝光变化等原因。为每帧保留时间戳、跟踪点数量和处理时延，再人为制造丢帧/时间间隔变化，观察状态是否正确重置或退化。

**学习资料：**[OpenCV 官方教程](https://docs.opencv.org/4.x/d9/df8/tutorial_root.html)

**知识点文档：**[经典计算机视觉方法](/vehicle-vision/development/classical-vision) · [视频时序与流式处理](/vehicle-vision/development/video-temporal-processing)

## 阶段 4：深度学习与视觉任务

先掌握张量形状和布局、数据加载、前向/反向传播、损失函数、优化器、学习率、正则化、增强和 checkpoint。建立训练/验证/测试数据隔离和可复现实验记录，再学习适合主线的任务。

### 深度学习通用基础

| 知识点 | 学习重点 | 实践时要检查 |
|---|---|---|
| 张量和计算图 | batch/channel/height/width 维度、数据类型、设备、自动求导 | 每层输入输出 shape、数值范围、CPU/GPU 设备是否一致 |
| 网络模块 | 卷积、归一化、激活、残差、多尺度特征、注意力/Transformer 的基本用途 | 不只背网络名称；能解释模块解决的问题及其算力/内存成本 |
| 损失函数 | 分类、回归、定位/分割损失；正负样本和类别权重 | 标签编码、损失分量与梯度是否合理；某一分量是否主导训练 |
| 优化和训练 | SGD/Adam 类优化器、学习率计划、权重衰减、梯度裁剪、混合精度 | loss 与指标趋势、梯度异常、随机种子和 checkpoint 恢复是否一致 |
| 泛化与过拟合 | 训练/验证差距、正则化、数据增强、类别不平衡和域偏移 | 按场景切片查看退化；避免只根据训练集 loss 判断模型质量 |
| 数据管线 | 标注读取、采样、批处理、缓存、增强与数据加载并发 | 数据变换后图像和标签仍然对齐；增强不会产生非法框/掩码 |
| 实验管理 | 代码/依赖、数据版本、配置、权重、随机种子、日志和评估脚本 | 能从结果追溯一次训练所用的完整输入与参数 |
| 推理概念 | 训练/推理模式、归一化、批处理、置信度阈值、后处理 | 推理路径与训练假设一致；阈值和后处理参数有版本记录 |

初学时先使用成熟框架建立可靠基线，再阅读模型结构和训练细节。复现基线时优先固定数据、评估脚本和预处理，再比较模型变化，避免同时改多个变量。

### 视觉任务知识点

| 任务 | 需要理解的概念 | 常见结果检查 |
|---|---|---|
| 分类 | 类别定义、类别不平衡、决策阈值、概率校准和拒识边界 | 混淆矩阵、各类召回、置信度分布、阈值变化影响 |
| 目标检测 | 框参数化、正负样本分配、分类/定位损失、NMS 或其他候选筛选、标签匹配 | AP、不同尺度/距离/遮挡切片的误检与漏检；框坐标是否映射回原图 |
| 语义/实例分割 | 像素标签、类别边界、前景/背景不平衡、掩码分辨率 | IoU/mIoU、边界质量、小目标和稀有类别分层 |
| 跟踪 | 检测与数据关联、外观/运动线索、轨迹生命周期、ID 分配和状态预测 | 轨迹连续性、ID 切换、短时丢失恢复、延迟和抖动 |
| 关键点/姿态 | 关键点 schema、可见性、遮挡、坐标归一化和几何约束 | 各关键点误差、遮挡分层、连续帧姿态抖动 |
| 深度/几何 | 深度定义、尺度基准、相机内参、有效区域和不确定性 | 距离误差、尺度漂移、远近分层、坐标与单位是否一致 |

评估需要区分任务指标与功能指标。AP、IoU 等用来衡量模型输出与标注的匹配；端侧延迟、输出有效率和下游功能效果需要另外定义测量边界。分母、类别集、匹配阈值、忽略区域和数据版本必须随结果保存。

**重难点：**离线总分无法说明模型是否适合目标功能。数据泄漏、标签规范、输入尺寸、置信度/NMS 参数和样本分布都必须与指标一起管理。

**练习与验收：**使用许可证明确的公开数据完成一个小型检测或分割基线；提交数据说明、标签检查、训练配置、评估脚本、逐样本可视化、错误分类和已知限制。再选取一组固定样本验证预处理和后处理：手算几个框的缩放/偏移映射，检查阈值变化如何影响 FP/FN，并确认评估脚本能复现结果。

**学习资料：**[PyTorch Tutorials](https://pytorch.org/tutorials/) · [COCO 评估说明](https://cocodataset.org/#detection-eval)

## 阶段 5：选择一个领域主线

完成通用基础后，把学习收敛到一个工作方向，并补齐相应的模型、几何和功能知识。

### 前视 ADAS

按项目需求学习目标检测/跟踪、车道线与道路几何、交通标志/灯、深度或运动估计，以及多传感器融合接口。重点处理小目标、远距离、遮挡、逆光、雨夜和时间连续性；了解感知结果如何服务于 FCW、AEB、LKA 等下游功能。

| 知识点 | 开发时要理解的内容 | 产出检查 |
|---|---|---|
| 道路目标感知 | 类别定义、截断/遮挡、目标尺寸变化、相对距离、运动模糊 | 预测框映射回原图正确；远距离、小目标和遮挡切片有单独分析 |
| 车道与道路几何 | 车道线/边界表示、曲线拟合、图像坐标到车体/道路坐标、道路曲率 | 几何输出带单位、坐标系和有效范围；弯道、坡道和汇入场景有检查 |
| 跟踪与运动 | 目标关联、速度/加速度估计、自车运动补偿、轨迹初始化和退出 | 目标 ID 生命周期合理；短暂遮挡后恢复策略明确，不以陈旧轨迹冒充当前观测 |
| 交通标志/灯 | 目标检测、状态分类、可见性、颜色/闪烁和时序确认 | 说明单帧输出怎样聚合为稳定事件，避免单帧噪声造成状态跳变 |
| 多传感器融合接口 | 时间同步、坐标变换、测量置信度、数据新鲜度和无效状态 | 每条输出可关联采集时间、坐标和有效标志；融合端知道数据何时过期 |
| 功能链路认知 | 感知输出如何进入 FCW、AEB、LKA 等下游功能 | 能区分感知模块能力和下游策略，不把模型指标直接当成车辆功能验收 |

**典型难点：**远距离小目标的像素信息有限；低太阳角、隧道出入口、雨滴/污渍等会同时改变成像和模型输入；单帧正确也可能因时序抖动导致功能不稳定。调试时同步看原始图像、预处理图、模型输出、跟踪结果和下游接口。

**知识点文档：**[前视 ADAS 感知开发](/vehicle-vision/development/adas-perception-development)

### 环视与泊车

重点学习鱼眼相机模型、多相机标定与同步、去畸变、鸟瞰变换和拼接；再按功能扩展车位、边界、障碍物和可行驶区域感知。重点检查拼接几何、相机接缝、车体遮挡和近场盲区。

| 知识点 | 开发时要理解的内容 | 产出检查 |
|---|---|---|
| 鱼眼与去畸变 | 镜头投影模型、有效视场、畸变参数和查找表 | 去畸变前后边缘区域有可视化；参数与具体相机/分辨率绑定 |
| 多相机标定 | 相机间外参、相机相对车体位置、安装公差和重新标定条件 | 变换链可追踪；不同相机帧时间差可测且有处理策略 |
| 鸟瞰变换 | 地平面假设、逆透视映射、地面坐标范围和采样分辨率 | 地面网格、车身轮廓和已知距离点投影位置正确；非地面物体的拉伸限制明确 |
| 拼接与融合 | 重叠区域、亮度/颜色差异、接缝策略、遮挡区域和车体遮罩 | 接缝与重影可视化；相机断流时不能输出看似完整的错误画面 |
| 车位与障碍物 | 线/角点/区域表示、车位拓扑、近场小目标、可行驶区域 | 输出几何与车辆坐标一致；边界、柱体、路沿和低矮障碍物分别检查 |
| 端到端延迟 | 多路图像并行处理、同步等待、队列和渲染开销 | 记录每路相机和拼接/感知各阶段时间，确认显示内容对应同一时刻 |

**典型难点：**拼接画面“视觉上连贯”不代表几何正确；非地面物体、车身振动、相机安装变化和时间错位容易形成错位或重影。除视觉观感外，应使用已知地面点、距离和车体边界做几何检查。

**知识点文档：**[环视与泊车视觉开发](/vehicle-vision/development/surround-view-development)

### 舱内 DMS/OMS

重点学习人脸/人体检测、关键点与姿态、视线或状态识别、红外成像和补光。针对眼镜、口罩、手部遮挡、不同身材/肤色、座椅位置和昼夜变化构造数据切片，并以隐私授权和最小化数据访问为前提。

| 知识点 | 开发时要理解的内容 | 产出检查 |
|---|---|---|
| 人体/人脸与座位位置 | 多人区分、座位区域、裁剪策略、乘员进出和遮挡 | 输出与座位/人员 ID 的对应关系清楚；座椅调整后仍按定义工作 |
| 关键点和姿态 | 人脸关键点、头部姿态、视线估计、姿态坐标和可见性 | 关键点置信度与遮挡状态可解释；姿态角度单位和参考坐标明确 |
| 驾驶员状态 | 疲劳/分心等状态所需的观测定义、时间窗和状态机 | 区分单帧线索与持续事件；阈值、窗口、事件开始/结束规则可配置和追踪 |
| 红外成像与补光 | 红外图像特性、补光不均、反射、眼镜反光和夜间曝光 | 用实际传感器数据检查眼部/面部可见性，避免只在可见光样本上推断夜间表现 |
| 乘员与座舱变化 | 身高体型、座椅位置、方向盘/手部遮挡、儿童座椅等变化 | 按人群和座舱配置做覆盖分析，记录未覆盖条件 |
| 隐私和数据管理 | 采集授权、用途限制、脱敏、访问控制、保留与删除 | 开发样本和日志有来源/用途记录；不需要的原始图像不长期保留 |

**典型难点：**视觉线索往往需要跨帧累积；单帧阈值难以兼顾误报和漏报。产品事件定义应与算法状态机、时间窗口和下游提示一致，且涉及人群表现时要检查数据代表性和偏差。

**知识点文档：**[舱内 DMS/OMS 视觉开发](/vehicle-vision/development/cabin-vision-development)

**练习与验收：**围绕一个可描述的功能需求做原型，展示输入、输出、失败样例、适用范围以及无法处理的情形；把算法输出与下游接口契约对应起来。为主线维护一张“输入条件—算法模块—输出—风险—验证证据”表，避免把 ADAS、环视和 DMS 的类别、几何或验收方式混成一套。

**开发知识点：**[视觉数据、训练与评估](/vehicle-vision/development/vision-data-and-training) · [可靠性、可观测性与数据闭环](/vehicle-vision/development/reliability-data-loop)

## 阶段 6：模型导出、端侧部署与优化

学习从训练 checkpoint 到推理服务的完整路径：导出模型、检查算子兼容、验证数值差异、实现预处理/后处理、绑定输入输出和动态形状，再在目标硬件上做端到端测量。根据平台能力学习 ONNX、TensorRT、OpenVINO 或厂商 SDK；具体选型由 ECU、工具链和项目约束决定。

| 知识点 | 需要完成的工作 | 关键问题 |
|---|---|---|
| 模型导出 | 冻结模型结构与权重，导出 ONNX 或目标 SDK 格式，记录输入输出名称、形状和动态维度 | 导出后算子是否受支持？动态 shape、后处理和自定义算子如何处理？ |
| 数值一致性 | 在同一输入上比较训练框架与部署引擎输出，逐层或逐张量定位偏差 | 误差来自浮点精度、算子实现、预处理，还是输出解析？哪些张量适合绝对/相对误差检查？ |
| 预处理/后处理 | 对齐颜色转换、缩放、归一化、padding、坐标反变换、阈值和 NMS | 端侧实现是否与训练/评估代码一致？边界坐标如何取整？ |
| 运行时配置 | 输入缓冲区、输出缓冲区、内存布局、流/队列、线程和错误码 | 缓冲区由谁创建/释放？推理失败是否会返回上一帧旧结果？ |
| 量化与精度 | FP16/INT8 等精度模式，校准数据，敏感层和精度回退策略 | 校准集是否代表夜间、小目标、远距离等关键切片？退化集中在哪里？ |
| 性能剖析 | 分段测量解码、颜色转换、预处理、推理、后处理、拷贝和队列等待 | 当前瓶颈是哪一段？优化后是否改变总体延迟或只是转移瓶颈？ |
| 目标平台 | 驱动、运行时、编译器、固件、功耗/温度状态和并发负载 | 开发机与目标设备差异是什么？测量是否在目标负载和热稳定状态下进行？ |

优化时先测量瓶颈，再考虑 FP16/INT8 量化、算子融合、内存复用、异步流水线、线程和数据拷贝。记录模型、编译器、驱动、固件和配置版本，并同时比较精度、延迟、内存、功耗/温度和长时间稳定性。

性能报告至少区分模型推理时间和端到端时间。端到端统计应包含预热策略、输入分辨率、并发路数、负载/温度条件、样本数、p50/p95 延迟和丢帧/超时数；平均值不能代表尾部延迟。持续运行还要关注内存是否增长、队列是否持续堆积以及设备是否因温度或功耗限制降频。

**重难点：**桌面 GPU 的批量推理性能不能代表车端 batch=1 的实时体验。只看模型内核耗时会漏掉图像解码、颜色转换、搬运、队列等待和后处理；量化后的数值误差也必须在代表性数据切片上检查。

**练习与验收：**把训练好的模型导出并在目标或明确标注的模拟设备上运行；用相同输入配对比较原始与部署版本输出，报告端到端 p50/p95 时延、帧率、丢帧/超时、峰值内存和精度差异。至少分析一例不一致输出，沿预处理、模型张量、后处理和坐标映射定位来源。若没有目标设备，报告必须清楚标注平台与结果的适用边界。

**学习资料：**[ONNX 文档](https://onnx.ai/onnx/) · [NVIDIA TensorRT 文档](https://docs.nvidia.com/deeplearning/tensorrt/latest/)（使用其他平台时改读对应厂商 SDK 文档）

**开发知识点：**[端到端性能剖析](/vehicle-vision/development/performance-profiling)

**知识点文档：**[模型导出与推理部署](/vehicle-vision/development/model-export-inference) · [端侧优化与量化](/vehicle-vision/development/edge-optimization) · [端到端性能剖析](/vehicle-vision/development/performance-profiling)

## 阶段 7：系统集成、可靠性与迭代

把视觉算法作为系统组件交付：定义输入/输出 schema、时间戳和坐标系；处理无效帧、掉帧、超时、相机断流、标定缺失和资源不足；支持日志、诊断和版本回滚。根据项目架构接入相机驱动、消息中间件、车辆状态和下游功能，同时避免在算法线程中做不可控阻塞。

| 知识点 | 设计要求 | 可以观测的证据 |
|---|---|---|
| 接口契约 | 输入图像格式、时间戳、标定版本；输出坐标、单位、置信度、有效状态和版本字段 | schema/接口文档、样例消息、边界值检查 |
| 时序与并发 | 回调线程、推理线程、队列容量、背压、帧淘汰策略和数据所有权 | 各阶段时间戳、队列深度、帧 ID、丢弃原因 |
| 错误与降级 | 无效帧、断流、超时、资源不足、标定无效时的状态机和恢复条件 | 错误码、状态转换日志、恢复时间和旧结果使用策略 |
| 资源生命周期 | 图像缓冲区、推理上下文、线程、文件句柄和模型资源的创建/释放 | 长时运行内存曲线、句柄/线程数和 sanitizer 结果 |
| 可观测性 | 结构化日志、输入摘要、版本、时间戳、输出状态、诊断码和性能统计 | 单次运行可串联输入、推理、输出与故障原因 |
| 配置与版本 | 代码、模型、数据、标注、标定、引擎、固件和阈值的组合关系 | 可回滚的发布清单和运行时版本报告 |
| 质量闭环 | 固定回归集、视频回放、场景仿真、台架与实车的分层验证 | 失败样例可复现，数据回流经过授权、脱敏和审核 |

建立模型、代码、数据、标注、标定、推理引擎和运行环境的版本关系。用固定离线集快速发现回归，再用视频回放、仿真、台架和道路验证补足各自覆盖。线上问题经过授权与脱敏后进入数据闭环，并保留数据来源和用途记录。

系统集成时应定义数据新鲜度：如果输出晚于功能需要的时间窗口，应报告过期或无效，不能只因为消息格式正确就当作有效。队列策略也应有明确选择，例如优先处理最新帧还是保证逐帧处理；选择取决于功能需求，并需要测量其对延迟和丢帧的影响。

**重难点：**“模型能运行”只证明链路局部可用。需要区分算法质量、时序/接口错误、传感器异常和下游功能问题；域外输入和不可用状态要有明确的降级或告警行为。

**练习与验收：**建立一个最小端到端版本流水线，包含构建、固定数据回归、机器可读指标、部署包版本和故障日志；模拟缺帧、延迟乱序、相机断流或超时，确认系统能报告状态并按设计处理。让另一位开发者按文档重跑，并从日志追踪一个输入帧对应的处理阶段和最终输出。

**开发知识点：**[视频时序与流式处理](/vehicle-vision/development/video-temporal-processing) · [视觉系统集成](/vehicle-vision/development/system-integration)

**知识点文档：**[视觉系统集成](/vehicle-vision/development/system-integration) · [可靠性、可观测性与数据闭环](/vehicle-vision/development/reliability-data-loop)

## 贯穿全程的知识清单

- **算法基础：**图像处理、几何视觉、目标检测/分割/跟踪、时序稳定、模型评估和错误分析。
- **工程基础：**C++、Python、Linux、CMake、Git、调试、性能剖析、并发、内存和日志。
- **数据能力：**采集条件、标签 schema、数据授权、样本切分、长尾场景、数据质量和版本追踪。
- **端侧能力：**模型格式与编译、预处理一致性、量化、算子兼容、端到端 profiling 和稳定性。
- **系统能力：**需求拆解、接口契约、相机/车辆信号链路、时钟与同步、故障诊断、降级和回归闭环。
- **专业责任：**用户隐私、道路数据授权、试验安全、适用法规和功能安全流程；具体要求以项目正式流程为准。

## 最小端到端项目

使用许可证明确的公开道路图像/视频和检测标注，完成一个前视目标检测原型：

1. 写清功能范围、目标类别、数据来源、许可和评估数据切分。
2. 完成图像检查、标签校验、模型训练或基线推理，并冻结代码/模型/参数版本。
3. 输出逐帧预测可视化及按类别、目标尺寸和昼夜条件分层的指标。
4. 将同一模型导出到推理格式，核对与原始框架的输出差异。
5. 在目标或模拟硬件测量端到端延迟和资源，记录未覆盖的摄像头/车辆功能路径。
6. 提交 README、运行命令、环境版本、错误样例、结果和局限，让另一位开发者能够复跑。

该项目用于学习算法与部署工程，不代表车规产品验证、道路安全结论或量产验收。

## 高级工程师能力标尺

**全部知识点文档：**[车载视觉开发知识点目录](/vehicle-vision/development/)

| 能力面 | 高级工程师应能独立完成 | 可检查的证据 |
|---|---|---|
| 需求和架构 | 从功能、场景、输出契约、平台资源和失效行为推导模块边界与方案 | 设计文档写明假设、约束、替代方案和验证办法 |
| 算法判断 | 选择合适任务和基线，解释模型结构、数据需求、适用范围及已知失败模式 | 以代表性样例和分层指标支持方案选择，而非只引用排行榜分数 |
| 数据闭环 | 发现数据缺口/标签问题，设计采集、筛选、授权、版本和回归流程 | 数据变更可追溯，新增样本能转成可复现的回归项 |
| 端侧工程 | 在目标硬件定位性能瓶颈，评估精度、延迟、功耗、内存和稳定性的取舍 | 端到端 profiling、配对精度对比和长期运行记录 |
| 故障诊断 | 从输入、成像、标定、预处理、模型、后处理、时序和接口逐层定位根因 | 故障报告包含证据、影响范围、修复和防止复发的措施 |
| 系统交付 | 定义无效/过期数据处理、降级、诊断、发布和回滚机制 | 集成文档、版本清单、故障演练和回滚记录 |
| 技术协作 | 组织需求、代码、模型、数据和部署配置的联合评审，指导团队复现问题 | 评审记录、共享工具和其他工程师可独立复跑的说明 |

高级能力的标志不是掌握更多模型名词，而是能讲清精度、延迟、功耗、数据成本与可维护性的取舍，识别未知条件，并把一个视觉功能稳定地交付到它真实运行的系统中。
