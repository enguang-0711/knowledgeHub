# 视觉代码与数据版本管理

## 版本边界

源码、构建脚本、schema 和轻量配置纳入 Git；图像/视频数据、标注集和模型由合适的数据/制品仓库保存。代码提交中保留数据版本 ID、manifest 路径、哈希和获取说明，避免把大型或受限原始数据直接提交。

## 实验追踪

每个训练/部署结果绑定代码提交、数据与标注版本、预处理、模型权重、类别映射、标定、工具链和硬件。版本更新生成可比较差异，不覆盖已发布制品。

## 评审重点

评审中检查 schema/类别变更、数据许可、标定影响、固定集回归和回滚方案。密钥、个人图像和位置数据不得进入普通仓库或公开 CI 日志。

## 练习与验收

完成一次数据集新增和模型更新，生成新 manifest 并保留旧版本。另一位开发者能根据记录重建相同训练/评估样本。

## 版本绑定与变更评审

一次训练/部署版本应能关联 Git commit、数据 manifest、标签 schema、预处理配置、模型权重、类别表、标定参数、推理运行时和评估器。大型数据和权重放入受控制品存储，仓库仅保留不可变 ID、哈希、许可说明和获取方式。

数据新增时生成新快照并比较样本 ID、场景分布和标签差异；不要移动或覆盖历史版本。评审检查切分是否改变、保护集是否被用于调参、是否引入敏感信息，以及失败时能否恢复上一模型/配置。

**验收产物：**从干净 checkout 复现一次训练或评估，验证权重与数据哈希；提供版本清单、差异报告和回滚命令。检测到未授权文件、哈希不符或缺失依赖时，流水线应明确失败而非静默跳过。
