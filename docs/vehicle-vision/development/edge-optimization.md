# 车载视觉端侧推理优化

## 优化目标

在目标 ECU 上同时满足精度、端到端时延、内存、带宽、功耗和温度预算。优化必须绑定硬件、模型、编译器、驱动与输入配置；桌面 GPU 或单次峰值不能替代车端长时结果。

## 常用方法

先剖析数据流，再选择算子融合、静态 shape、图优化、算子替换、减少布局转换、复用缓冲、零拷贝、流水并行或线程亲和等方法。小 batch 降低等待但可能降低吞吐；多线程也可能因带宽竞争反而变慢。

量化是独立优化手段，需同时测精度和资源，详见[视觉模型量化](./quantization)。模型格式/图优化见[模型导出](./model-export)，设备执行见[推理运行时](./inference-runtime)。

## 评测和回退

在相同输入与固定精度基线上比较 p50/p95/p99 延迟、吞吐、峰值内存、功耗、温度和任务分层指标。确认加速器算子没有悄悄回退 CPU，且长时运行没有热降频或资源增长。任何精度越界都需停止发布或回退。

## 练习与验收

对一条端到端检测 pipeline 逐段计时，选择一个瓶颈实施优化，再以固定视频和目标 ECU 比较收益/回退。交付复现命令、环境清单、场景指标和回滚方案。

## 端侧优化实验方法

先建立目标设备上的稳定基线：固定模型、输入、运行时/驱动、功耗模式和温度条件，预热后采集分阶段时间、端到端 p50/p95/p99、峰值内存与精度。区分异步设备提交与实际完成时间，避免 profiler 只量到 CPU enqueue。

每次只优化已证实的瓶颈，例如减少颜色转换/布局搬运、复用缓冲、融合算子、降低同步点或调整线程。优化后用相同输入、相同热状态重测；若推理核变快但队列或后处理变慢，应看端到端净收益。

**验收产物：**优化前后资源与分层质量对照、设备/工具链清单、回滚开关和长时运行结果。任何场景精度超限、热降频、内存增长或帧龄变大时，应停止该优化并定位原因。
