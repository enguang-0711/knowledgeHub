# 可靠性、可观测性与数据闭环

视觉功能上线后的可靠性依赖故障处理、可诊断证据和受控的数据改进流程。模型更新不能绕过版本、隐私和回归管理。

## 可靠性设计

为图像无效、相机断流、标定缺失、推理超时、资源不足和运行时崩溃定义检测方式、状态输出、恢复条件和超时策略。明确何时可短暂沿用上一结果、何时必须标记过期或降级。看门狗、重启和回滚行为需避免反复故障循环。

## 可观测性

结构化日志至少关联运行 ID、帧 ID/采集时间、模型/代码/配置版本、阶段耗时、输出状态和错误码。性能指标记录分位数、丢帧、资源、温度和队列状态。诊断数据应能从功能异常追到原始输入或其受控引用，但只保留必要信息。

## 数据闭环

线上或道路问题需要有授权依据。候选样本经隐私处理、质量审核、标签确认和场景归类后，才能进入训练或回归集。保存来源、用途、许可、标注和处理版本；样本筛选或标签变更应可追踪。

数据更新后重新评估固定基线及关键切片。模型、代码、数据、标定和推理引擎组成联合发布版本；异常时能回退到已知版本。AI 生成的标签或场景描述需人工或规则校验。

## 练习与完成标准

模拟相机断流、模型超时和内存压力，验证错误码、状态转换、恢复时间及日志关联。再定义一个问题样本从发现到审核、入库、回归和发布的流程。交付物需包含授权/隐私检查点与版本追踪示例。
