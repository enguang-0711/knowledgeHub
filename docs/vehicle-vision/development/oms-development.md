# 乘员监测 OMS 开发

## 功能范围

OMS 可能包含座位占用、乘员数量/位置、乘员状态、安全带或遗留物提醒。每个功能使用不同标签与错误代价，应分别定义输出、适用座位、置信度、状态更新和错误处理。

## 感知和状态推理

算法通常结合区域检测、人体姿态/属性和跨帧状态逻辑。儿童体型、毯子/衣物、背包等物品、座椅移动、遮挡和不同光照都会造成歧义。系统应能表示空座、占用、不确定和传感器无效等状态。

## 数据与隐私

建立覆盖不同人群、座椅、姿态和物品的授权数据集；标注人/物/座位归属并记录不确定样本。只收集功能所需图像并限制存储和训练用途。

## 练习与验收

实现简化座位占用识别状态输出，覆盖空座、成人/儿童、物品、遮挡和摄像头故障。报告分座位混淆矩阵和不确定状态处理。

## 把乘员感知拆成可验证输出

先定义功能是座位占用、乘员数量/位置、安全带、儿童遗留还是物品检测；每个功能有独立标签、未知状态、更新周期和错误代价。人员与座位关联需要处理上下车、多人交叉、儿童座椅及物品遮挡，不能只输出“有人/无人”。

数据按座位、体型/年龄段、姿态、衣物/毯子、遮挡、座舱配置和红外/可见光条件分层；建立“可确认、不可确认、传感器无效”区分。输出座位状态变化时，记录帧时间和置信度，避免短暂遮挡触发来回跳变。

**验收产物：**对每项功能分别提交混淆矩阵/事件指标、空座物品与乘员遮挡错例、隐私处理记录和无效输入响应。涉及儿童或安全提醒时，评估要有明确风险审查和独立保护集。
