# 端到端性能剖析

视觉系统性能应从采集输入到输出发布测量。单独报告模型推理耗时，会遗漏解码、颜色转换、数据搬运、排队、后处理和同步等待。

## 分段计时

至少为每帧关联以下时间点：采集、接收、解码、预处理开始/结束、推理开始/结束、后处理、输出发布。计算各阶段耗时、端到端耗时和数据年龄。多相机系统还要分别统计每路输入及融合等待。

## 统计口径

报告样本数、预热次数、输入分辨率、并发负载、运行时版本、目标设备和温度/功耗状态。使用 p50/p95 等分位数呈现尾部延迟，并同时报告帧率、丢帧、超时、队列深度、CPU/加速器利用率和峰值内存。平均值无法表达抖动和尾部风险。

## 定位瓶颈

先用系统追踪或 profiler 确认耗时在 CPU、加速器、数据传输还是队列等待。运行期间观察热状态和长时间趋势。性能优化前后需使用同一输入与配置；避免并发任务或后台负载造成不公平比较。

## 常见误区

- 预热未完成就计时，包含初始化开销。
- 只测推理调用，忽略输入复制和同步。
- 以 GPU 理论吞吐推断车规 ECU 实时能力。
- 只测短时峰值，没有检测热降频、内存增长和队列积压。

## 练习与完成标准

为视频回放程序增加阶段计时和帧 ID；输出 p50/p95、帧率、丢帧和队列深度。在输入速率高于处理能力时验证队列策略，并用 profiler 找出至少一个实际瓶颈。交付完整测量配置与可复现结果。
