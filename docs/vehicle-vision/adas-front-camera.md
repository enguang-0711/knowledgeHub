# 前视 ADAS 摄像头感知测试

前视摄像头的视觉测试要分清“图像里识别了什么”“感知输出怎样进入功能”和“车辆/HMI 最终做了什么”。FCW、AEB、LKA/LDP 等功能可能使用摄像头以外的传感器、融合策略和车辆状态；单独验证图像模型不能证明整车功能已经通过。

## 名词与系统边界

- **ADAS（Advanced Driver Assistance Systems）**：高级驾驶辅助系统的统称，具体功能和责任边界依车型/产品定义。
- **FCW（Forward Collision Warning）**：前向碰撞预警，通常给出警告相关输出；其触发规则以需求为准。
- **AEB（Automatic Emergency Braking）**：自动紧急制动功能；本页只讨论测试分层，不提供道路试验操作指引或安全阈值。
- **LKA/LDP**：车道保持辅助/车道偏离预警，命名、功能和执行能力在不同产品间可能不同。
- **TTC（Time To Collision）**：碰撞时间估计的一类量，常基于距离与相对速度假设；在目标加减速、横向运动或速度接近零时解释有限。
- **目标列表/车道模型**：把图像模型结果转换成下游可消费的结构化目标、轨迹或几何边界。

常见链路：

```text
前视镜头/传感器 → ISP/图像校正 → 目标/车道感知 → 跟踪与运动估计
→（可选）多传感器融合 → 功能逻辑/状态机 → HMI 或车辆执行接口
```

测试计划先画真实架构，标注相机输入点、标定/时间同步、模型输出接口、融合输入、功能状态、HMI/车辆信号、日志和版本。每个用例注明覆盖到链路哪一段、哪些组件被旁路。

## 一、感知对象与输出契约

前视感知可能输出车辆、行人、骑行者、交通标志/信号灯、车道线/道路边界、可行驶区域或自由空间。每种输出都要冻结：类别枚举、坐标系、单位、置信度含义、时间戳、有效标志、生命周期、无效值、排序和协议版本。

目标框与三维目标是两种不同表示。若接口包含距离、横向位置、速度或朝向，必须知道真值来源与误差；不能从二维框 IoU 推断几何量准确。坐标转换、车辆姿态补偿、时间同步和目标跟踪都可能影响下游事件。

## 二、测试分层

1. **输入/成像层**：分辨率、曝光/HDR、镜头污损、挡风玻璃反射、遮挡、帧时间戳、丢帧和图像格式。
2. **模型/感知层**：类别漏检/误检、框/位置误差、置信度、远近小目标、遮挡、标志/车道输出。
3. **跟踪/估计层**：轨迹创建/消亡、ID 切换、速度/位置抖动、遮挡后恢复、时间延迟。
4. **功能逻辑层**：状态进入/退出、告警时机、抑制条件、驾驶员接管或退出要求；按项目需求验证。
5. **整车/HMI 层**：告警展示、声音/图标状态、总线事件、执行请求和车辆状态的时间关联。道路或封闭场地验证需遵循经批准的安全计划。

## 三、关键场景与预期结果

- **目标距离/尺度**：分近中远、像素尺寸与相对速度；每一切片报告漏检和位置/时延误差。
- **遮挡与切入**：前车遮挡行人/骑行者、车辆从相邻车道切入、目标短时出画再出现；检查检测和轨迹连续性。
- **道路几何**：直路、弯道、坡道、匝道、车道收窄/分合、施工改道和磨损标线；检查车道身份和横向偏差。
- **光照/天气**：逆光、隧道出入口、夜间车灯、湿路反光、雨雪污渍、阴影和 LED 闪烁；区分传感器饱和与模型错误。
- **标志/信号灯**：尺寸、角度、遮挡、褪色、临时标志、相似外观和多目标并列；记录类别、状态与置信度。
- **车身运动/同步**：俯仰、振动、转弯、曝光变化、多传感器时钟偏移；看输出抖动、定位偏差和事件先后。

不要只写“应正确识别”。将需求转成可测断言，例如目标是否在限定帧窗内出现、类别和位置允许范围、轨迹是否连续、功能事件是否在指定条件下进入/退出。具体阈值必须引用产品需求或验证规范。

## 四、指标与结果解释

模型层至少按类别/距离/尺度/光照/遮挡报告 TP、FP、FN、precision、recall、定位误差和置信度分布；序列层增加 ID switch、轨迹中断、启动/恢复延迟；车端层增加输入到输出时延、p95/p99、帧间隔、超时、丢帧和资源占用。若输出传入下游功能，应同时报告“感知正确率”和“功能事件结果”，不把两者混成一个成功率。

发现功能漏报时沿链路逐层定位：输入是否含目标且质量合格 → 标注是否一致 → 模型是否输出 → 输出是否有效/及时 → 融合是否保留 → 功能条件是否满足 → HMI/执行接口是否响应。日志应带共同时间基准、相机帧 ID、目标 ID、功能状态和车辆信号。

## 五、错误注入与边界行为

在安全的离线/SIL/台架范围，可注入缺帧、重复帧、时间戳跳变、图像过曝/欠曝、相机失联、标定版本错配或无效目标输出，检查诊断、降级和恢复行为。测试设计应避免在未批准的真实道路环境中人为制造危险输入。

检查启动、停止、重启、温度/负载升高、配置切换和故障恢复时输出状态；确认 stale（过期）目标不会被当成实时目标，异常状态有明确诊断，恢复后无需留下旧轨迹。接口错误要区分“模型没有检测”和“消息未发布/被丢弃”。

## AI 时代的实践

视觉语言模型可辅助从视频检索“施工线与旧车道线并存”等候选片段，也可生成缺陷摘要；传统检测模型与 VLM 的能力、延迟和可复现性不同。用于自动驾驶闭环的任何 AI 结果都要回到已版本化帧/片段、结构化标签和确定性判定。LLM 评审可给调查建议，不能单独裁决安全功能 pass/fail。

## 动手练习与验收

用公开许可视频或合成示例搭一个非车辆执行的离线练习：定义目标/车道 schema；选取至少 3 个场景片段（如远处小目标、遮挡重现、隧道明暗转换）；输出帧级预测、逐场景指标、时间线和错误可视化；模拟缺帧或时间戳偏移，确认异常可观测。验收报告要明确未覆盖融合、功能 ECU、HMI 或道路安全验证。
