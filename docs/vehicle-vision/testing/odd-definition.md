# 视觉系统 ODD 定义

## ODD 内容

运行设计域（Operational Design Domain, ODD）描述功能设计运行的道路、速度、天气、光照、交通、区域和传感器条件。ODD 应能被数据标签或运行时信号识别，不只是自然语言列表。

## 域内、边界与域外

测试应覆盖典型域内条件、边界过渡和明确域外情况，例如强眩光、镜头遮挡、浓雾或超设计速度。系统应能给出适当能力状态、告警或降级，而不是对域外输入作无条件承诺。

## 版本管理

ODD 定义随功能、相机和模型变化而版本化。每项域条件需有证据来源、阈值、组合逻辑与责任方；定义改变后要重新评估测试覆盖和数据代表性。

## 练习与验收

为一个低速泊车功能定义 ODD 表格，列出可观测信号和域外动作。设计边界样例证明条件能被检测并留下证据。

## 把 ODD 条件映射为测试

每个条件写成可观测字段、范围/阈值、来源、组合关系和域外动作，例如车速、道路类型、照度、降水、镜头遮挡或传感器健康状态。定义域内、边界、过渡和明确域外样本；对无法在线测量的条件说明如何通过场景标签或外部设备确认。

**验收产物：**版本化 ODD 表、需求追踪关系、覆盖矩阵和域外状态证据。阈值变更后评估受影响的数据集、测试用例及降级策略；只有自然语言描述而无法映射到信号或可审查场景的条目应标为待补充。
