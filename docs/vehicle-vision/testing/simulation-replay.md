# 视觉仿真、视频回放与 SIL/HIL

仿真和回放把难以反复遇到的场景变成可重跑输入，但每一种注入方式覆盖的系统边界不同。测试报告必须回答：喂进去的是什么、真实经过哪些组件、哪些传感器/功能被替代，以及结论可以外推到哪里。

## 名词拆解

- **离线回放**：把采集图像/视频或传感器记录重新送入算法/软件。若直接送预处理后图像，可能绕过摄像头与 ISP。
- **SIL（Software-in-the-Loop）**：软件在主机或仿真环境中运行，与虚拟传感器、车辆/场景模型交互。
- **HIL（Hardware-in-the-Loop）**：真实 ECU/硬件接入实时仿真环境，由仿真设备提供输入或信号并观察输出。
- **场景仿真**：通过道路、参与体和事件参数描述构造测试输入。图像渲染器、传感器模型和车辆动力学模型都有各自误差。
- **传感器回放**：重放多路图像及时间戳，需保持相机 ID、帧顺序、时钟和同步关系。
- **确定性/可复现性**：同一版本、配置、输入和随机种子得到可解释且足够一致的结果；并非所有 GPU/并行管线都能逐位确定。

## 一、测试层级与适用问题

| 层级 | 适合回答 | 主要盲区 |
|---|---|---|
| 单帧离线 | 模型/预处理的精度变化 | 视频时序、同步、摄像头硬件、端侧实时性 |
| 视频/多相机回放 | 跟踪、时间戳、帧丢失、同步逻辑 | 实际光学、传感器噪声、真实 ISP（取决于注入点） |
| SIL/场景仿真 | 功能逻辑、参数扫描、边界和危险场景 | 仿真与现实域差异、真实 ECU 性能（除非连接目标硬件） |
| HIL/台架 | ECU 接口、实时性、诊断、硬件负载 | 真实道路/天气覆盖及所有成像现象 |
| 封闭场地/道路 | 系统真实成像与整车行为 | 成本、安全约束、稀有场景复现和环境控制 |

该表是定位工具，不是质量等级排名。每次执行要有明确目标和边界；多个层级串联可以补覆盖，但一层通过不能推导另一层通过。

## 二、回放输入与时间对齐

回放包至少保存媒体哈希、解码器/编码格式、分辨率、帧率、每帧时间戳、相机 ID、丢帧标记、车辆/传感器信号时间、标定与软件配置、场景标签和许可信息。多相机用一个同步组 ID 关联同一采样时刻，并记录时钟源和时间戳转换。

回放前做完整性检查：媒体长度和帧数、时间戳单调性/重复/跳变、帧率分布、首尾丢帧、相机映射、信号长度和标定配置。回放时确认系统按原时钟、加速时钟还是实时运行；如果速度改变，时序滤波、超时和融合行为可能不同。

重放闭环应含输入选择 → 环境配置 → 清理上次状态 → 注入/同步 → 输出采集 → 结果判定 → 证据归档。失败时保留原始日志和可重复命令；不要只保留汇总分数。

## 三、仿真场景的设计与验证

将逻辑场景参数化：道路几何、目标类别/轨迹、天气/光照、相机视场/噪声/曝光、车速和传感器时钟。固定场景文件版本、仿真器版本、传感器模型、渲染选项、随机种子和软件构建。对随机噪声测试，运行多 seed 并报告分布。

先做仿真有效性检查：目标轨迹是否符合预期、深度/遮挡关系正确、帧时间戳和相机姿态合理、渲染图像分辨率和曝光范围合理。场景描述通过语法验证不代表渲染结果真实；应抽样检查图像、关键状态和真值标签。

仿真与真实数据差异可能来自材质/纹理、传感器噪声、运动模糊、镜头污损、曝光/HDR、反射、参与体行为、标定误差和压缩链路。挑选有真实采集对照的切片，比较像素/统计分布及模型输出；对不能模拟的因素明示排除。

## 四、SIL/HIL 故障与恢复测试

在授权环境中注入图像帧丢失、重复/乱序、相机掉线、时钟偏移、数据包延迟、过载、异常分辨率、无效标定和模型输出缺失。验证监控、超时、降级、故障码、状态清理和恢复时间。定义预期状态迁移，不只判断进程是否崩溃。

HIL 需同步记录 ECU 固件/模型/标定、目标硬件、实时仿真时钟、输入输出接口、总线负载、供电/温度、调度和所有信号版本。注意真实 ECU 运行时的定时约束；离线加速重放不等于实时闭环测试。

## AI 辅助场景生成

LLM 可把自然语言缺陷转成场景参数草案，生成后必须通过 schema、范围、单位、相对运动、碰撞/可见性、时间连续性和预期结果校验。VLM 可从海量视频检索候选事件，但候选时间戳和标签要人工或确定性算法确认。将提示词、模型、审核和转化脚本纳入版本记录；不要让模型自行宣布场景通过。

## 常见重难点

- **回放结果与实车不同**：核查输入注入点、解码/ISP、时钟速度、预处理版本、硬件负载和相机同步。
- **同一回放结果变化**：查随机种子、异步执行、非确定性算子、GPU/驱动版本、残留状态及数据顺序。
- **多路相机拼接异常**：按同步帧组、相机 ID 和标定 ID 查错配；文件名顺序不能保证同步。
- **场景仿真覆盖数字高却发现不了故障**：确认执行成功、真值正确、模型覆盖有效，并分析仿真到现实的差异。
- **HIL 用例不稳定**：核查实时步长、接口负载、ECU 调度、温度/功耗和超时定义。

## 动手练习与验收

选一段许可清楚的多帧视频，做带帧哈希和时间戳的 manifest；分别以正常顺序、缺帧、时间戳偏移运行同一处理链；比较轨迹与事件时刻；再定义一个参数化场景并做多 seed 运行。提交场景文件、软件/配置清单、运行命令、原始输出、差异报告与限制说明。不能接 HIL 时，将其标注为离线/SIL 练习。
