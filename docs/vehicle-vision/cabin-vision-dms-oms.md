# 舱内视觉：DMS 与 OMS 测试

舱内视觉面向驾驶员或乘员状态，常见输入是近红外/可见光摄像头及座舱环境信息。这里的目标、标签和错误代价与道路目标检测不同：同一张脸在遮挡、姿态和光照下可能变化很大，且图像属于高度敏感数据。本专题分别说明 DMS 与 OMS，具体功能必须以车型需求和适用法规为准。

## 专有名词

- **DMS（Driver Monitoring System，驾驶员监测系统）**：监测驾驶员注意力、视线、疲劳或状态的系统。不同产品支持的状态集合不相同。
- **OMS（Occupant Monitoring System，乘员监测系统）**：监测车内乘员、座位占用、姿态或遗留风险等状态的系统。
- **NIR（Near-Infrared，近红外）**：常用于暗光下成像的近红外光源/传感器组合；眼镜镜片和材质可能产生反射差异。
- **关键点/landmark**：眼角、鼻尖等用于估计姿态或视线的图像位置。关键点可见性与检测置信度需要单独表示。
- **凝视（gaze）与头姿（head pose）**：分别估计眼睛注视方向和头部方向，不能把头转向直接等同于视线离路。
- **占用（occupancy）**：某个座位区域是否有人/物；应定义儿童、宠物、座椅空置和物体放置等目标范围。

## 一、系统链路与功能边界

```text
舱内摄像头/照明 → 曝光与图像预处理 → 人脸/人体/关键点
→ 头姿/视线/状态或座位占用估计 → 时间滤波/阈值/功能逻辑
→ 提示、记录或车辆接口
```

测试前明确摄像头安装位置、视场、NIR 波长/照明策略、帧率、座椅配置、方向盘/遮阳板影响、支持的人群/状态、输出接口和提示逻辑。明确是否同时使用方向盘、车辆运动、座椅传感器等输入。DMS 算法输出与“驾驶员监测功能正确触发”必须分层验证。

## 二、DMS 测试维度

- **姿态和位置**：正视、低头、侧转、后仰、身体偏移、座椅前后/高度变化、方向盘遮挡。
- **视线/注意力**：道路注视、后视镜/仪表查看、短暂扫视、持续离路；需求要定义行为持续时间和状态边界。
- **遮挡与外观**：普通/偏光/深色眼镜、反光镜片、口罩、帽子、发型、胡须，以及手/手机等局部遮挡。
- **光照**：白天侧光、背光、夜间、仪表/屏幕光、隧道转换、NIR 反射、照明失效或过曝。
- **驾驶员差异**：身高、肤色、眼型、年龄特征等需基于授权、合理覆盖和公平性审查设计；避免仅对单一开发人员调试样本表现良好。
- **时序状态**：状态进入/退出延迟、短时抖动、连续帧丢失后恢复、车辆启动/停止/驾驶员切换。

疲劳/注意力标签难以只靠单帧判定。测试真值应由清楚的行为协议、多名复核者或专门设备建立，保留事件时间窗和不确定区域；不要把主观表情判断当作确定的医学结论。

## 三、OMS 测试维度

覆盖前/后排和不同座位、成人/儿童目标边界（仅按项目允许数据和方法）、座椅空置、物品放置、儿童座椅/安全带/头枕遮挡、乘员躺卧/弯腰、上下车过渡和多人同时进入。区分系统承诺的“人体存在”“座位占用”“姿态分类”与安全功能状态，避免把箱包误认为人体或因遮挡漏掉乘员。

若 OMS 触发遗留提醒或其他车辆行为，检查触发条件、抑制条件、状态持久性、点火/锁车周期、错误提示和故障诊断。每个状态定义要区分“未检测到人”“输入质量不足”“摄像头故障”和“功能禁用”。

## 四、评估与错误分析

分类/状态可报告混淆矩阵、每类 precision/recall、事件级召回/误报、状态切换延迟、抖动次数和无效/不可判定比例；关键点可报告归一化位置误差和可见点命中；人体/人脸检测可报告检测指标。所有指标按座位、光照、遮挡、眼镜类型、姿态、相机配置等切片，并显示独立人员数与样本数。

评测需避免同一个人的近重复视频跨入训练和测试。以个人/采集批次隔离比按帧随机切分更合理；人脸数据的去重和跨集隔离必须在隐私授权允许的环境内实施。事件级指标要先规定一次连续行为算一个事件还是多个事件。

失效排查路径：图像/照明质量 → 人脸/人体可见性 → 关键点与姿态 → 状态分类/时间滤波 → 车辆状态条件 → 提示/UI/总线。保存的诊断证据应控制访问、脱敏并设置删除期限。

## 五、隐私、公平性与数据治理

车内人脸、眼睛、身体姿态、行程和驾驶习惯都可能构成敏感个人信息。采集前确认合法依据、告知/授权、用途限制、最小必要范围、存储位置、访问审批、传输加密、脱敏方案、保留时间和删除流程。用于模型开发的数据不得自动扩展到其他目的。公开报告应删除可识别样本和个人信息。

按合理适用的人群和环境审查性能差异，记录样本覆盖不足和置信区间。小样本上的组间差异需要进一步收集合规数据，不能下过强结论。模型生成或合成的人脸数据也要标明来源、适用边界和潜在身份/偏差风险。

## AI 时代的辅助方式

多模态模型可以帮助生成场景标签候选、查找遮挡/反光片段或概括失败模式；面部状态最终判定必须依赖经审核的真值和明确的事件定义。不得将通用 VLM 对“看起来疲惫”的描述直接当作 DMS 金标签或驾驶员健康结论。

## 动手练习与验收

仅使用明确许可的公开或合成匿名样例，设计 DMS 或 OMS 的测试矩阵；写出状态定义和不确定样本规则；按人员/片段隔离数据；实现混淆矩阵、事件级时延和分层报告；产出脱敏错误可视化和数据治理说明。验收要说明镜头/车辆功能边界、隐私处理、样本局限与无法验证的整车行为。
